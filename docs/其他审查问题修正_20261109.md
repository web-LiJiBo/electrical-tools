# 其他审查问题修正（2026-11-09）

本次承接多设备、多动作更新，修正此前用户视角审查记录中的其他问题。本次代码与修正文档发布到更新分支 `feature/multi-device-actions-20261109`，未合并到远端 `main`。

海上风电的设备补充由其他人员负责，本次不包含该场景的数据、模板或目录查询扩展。

## 修正内容

| 原问题 | 当前行为 |
| --- | --- |
| 用户假设 OD 冷却，仍按当前 ON 工况的 65K 比较平均温升 | 假设数值及冷却方式共同参与评估，OD 对应原文 70K，ON/OF 对应 65K；当前快照单独计算。仅提供平均温升时，不判定整体正常。冷却方式冲突时返回不确定。 |
| 第二问失败，切换页签恢复第一问旧答案 | 开始新分析即清除旧结果并禁用旧预览；失败后切换页签保持本次错误。处理中编辑输入后，过时响应不保留“处理中”。 |
| 迟到的旧快照覆盖执行后的新状态 | 同一页面按读取序号和同会话状态版本拒绝回退，仍使用一份共享设备状态。 |
| 下发响应丢失，回答页仍称尚未执行 | 两个页签统一显示“执行结果未确认”，禁用原指令，要求查询状态并重新分析；不自动重试。 |
| 自动识别入口请求 normal，未复位子场景高温 | 同时检查子场景工况，必要时调用整体 normal 恢复。此操作是明确的模拟工况设置。 |
| 模板保存后首页运行目录仍旧 | 保存接口同步运行目录及现有会话的设备配置，保留设备状态，增加受影响会话版本，使旧预览不能直接执行。首页刷新或重新分析后使用新模板。 |
| 模板页初次连接失败，重连后按钮仍禁用 | 成功刷新目录后恢复校验、保存按钮。 |
| 合法 8 档被模型字段别名误拦截 | 补充“调压装置档位／有载调压装置档位”规范化；继续执行整数、范围及附加条件校验。 |
| 未知 action 导致内部错误 | 复验未知动作返回可理解的阻断说明；补充单设备分支的动作类型检查。 |
| “先别／暂缓”仅依赖模型保留否定条件 | 增加确定性否定保护，即使模型漏掉否定也不生成无条件预览。 |

主变与附属设备比较遗漏的已有本地修正继续保留，见[主变与附属设备比较修正](主变与附属设备比较修正_20261109.md)。本次没有更改其他业务场景的设备编号或名称。

## 本轮实际使用的验证问题

以下记录对应撤回海上风电改动后的最终验收，问题原文保持与验证脚本一致。模型输出可能随调用变化，下表记录本次实际结果与核对标准。

### 在线 API 问题（7 个）

共同条件：在线模式，选择“变电站设备运维”，开启模拟模式；使用新建的全设备会话，初始工况为 normal，分析限定在变电站场景。除 Q03 外，页面业务参数保持 `{}`。调用 `/analyze`，本组只查询或生成预览，不点击模拟下发。

| 编号 | 实际输入问题 | 额外业务参数 | 预期与本次实测结果 |
| --- | --- | --- | --- |
| Q01 | 假设主变1绕组平均温升70K，OD冷却，其他参数不提供，按该假设是否越限？ | 无 | 实测返回 `uncertain`；假设平均温升按 OD 上限 70K 比较，该单项未越限，但其余参数不完整，不判定整体正常。当前 ON 快照另行评估，无控制指令。 |
| Q02 | 假设主变1绕组平均温升70K，ON冷却，其他参数不提供，按该假设是否越限？ | 无 | 实测返回 `answered`；假设平均温升 70K 高于 ON 上限 65K，假设评估为 `abnormal`，与当前模拟状态分开显示，无控制指令。`answered` 表示已回答，不代表设备正常。 |
| Q03 | 请让SIM-IEC-FAN-01开始转动 | `{"action":"unsupported"}` | 实测返回 `uncertain`，提示设备未配置所请求的操作，无预览、无多指令列表，不返回 HTTP 500。此题必须携带未知动作参数才能复现原输入边界。 |
| Q04 | 将主变1的调压装置设定为8档 | 无 | 实测返回 `generated`；目标为 `SIM-IEC-TAP-01`，动作为 `set_tap`，工程值及协议值均为 8 档；仅预览，未执行。 |
| Q05 | 先别启动主变1的冷却风机 | 无 | 实测返回 `uncertain`，说明用户否定或取消操作，不生成启动预览或多指令列表。 |
| Q06 | 暂缓将主变1调压装置设为8档 | 无 | 实测返回 `uncertain`，保留暂缓含义，不生成档位调整预览或多指令列表。 |
| Q07 | 比较主变1与主变1的冷却风机当前状态 | 无 | 实测返回 `answered`；设备列表同时包含 `SIM-TRANSFORMER-01` 和 `SIM-IEC-FAN-01`，显示各自当前状态，不遗漏主变，不生成操作指令。 |

7 个问题的理解来源均核对为 `deepseek_api`。每题分析后重新读取同一会话，与分析前快照逐项比较，状态均保持一致。

### 真实浏览器中的输入与恢复步骤

使用首页默认“自动识别（推荐）”、模拟模式和新建的正常会话，按 B01—B03 顺序执行。B04 在模板管理页执行。延迟快照、丢弃响应和首次断连由浏览器测试脚本注入；它们是受控故障条件，单独输入问题不会必然触发这些故障。

| 编号 | 实际输入或操作 | 验证步骤 | 本次实测结果 |
| --- | --- | --- | --- |
| B01 | 启动SIM-IEC-FAN-01 | 暂扣首次设备快照；分析后在“操作建议”点击“模拟下发”；读到执行后状态，再释放旧快照。 | 在线分析返回 `generated`，显式启动成功，后端 `running=true`；旧快照释放后页面仍显示运行状态，没有回退。 |
| B02 | 问题填写“第二问”，业务参数填写 `{坏JSON` | 在 B01 后点击分析，看到失败提示，再切换“回答”页签。 | 持续显示业务参数须为合法 JSON 的本次错误，状态为“请求失败”，没有恢复上一问答案。本题在前端校验时终止，不计入在线模型调用。 |
| B03 | 停止SIM-IEC-FAN-01 | 将业务参数恢复为 `{}`；在线分析后点击“模拟下发”；脚本让停止请求实际到达后端，但丢弃响应；再切换“回答”页签并查询后端状态。 | 在线分析返回 `generated`；操作页与回答页均提示“执行结果未确认”，原指令不能继续直接下发；后端查询确认 `running=false`。不把网络失败解释成未执行，也不自动重试。 |
| B04 | 模板管理页首次读取失败后，点击“补充模板”→“刷新列表” | 脚本只阻断第一次模板目录请求，随后恢复真实连接，再刷新目录。 | 首次失败后按钮禁用；成功刷新后“校验并测试”和“保存补充模板”按钮恢复可用。此项没有提交新的模板，也不调用问题理解模型。 |

浏览器最终验收共 2 次真实在线分析、2 次明确模拟执行，四项恢复检查均通过，页面异常为 0。

### 其他回归使用的输入与边界

这些项目由 Python／Node 受控回归验证，与上述真实在线问句、真实浏览器验收分开记录。

| 项目 | 实际测试输入或条件 | 验证结果与层级 |
| --- | --- | --- |
| 自动识别恢复正常工况 | 同一全设备会话的子场景为 `high_temperature`，自动识别入口准备参数包含 `simulation_condition: "normal"`。 | Node 页面逻辑回归确认发出工况恢复请求，没有被顶层 normal 状态跳过。 |
| 模板保存同步 | 为现有 `SIM-MB-FAN-01` 补充 `alarm` 模板：功能 `mock_alarm`，条件 `alarm_permission == 1`，值 `true`；Modbus 映射为从站 3、地址 10、功能码 5、类型 bool；测试事实 `alarm_permission=1`。 | Python 类及应用内 HTTP 路由回归使用临时保存文件，确认运行目录和既有会话配置同步、设备状态保留、版本增加、旧预览执行被阻止；没有向本地正式模板配置写入该测试模板。 |
| 模型漏掉否定条件 | “先别启动主变1的冷却风机”“暂缓将主变1调压装置设为8档”，配合不含否定条件的受控模型理解结果。 | Python 回归确认本地确定性保护仍阻断操作；不是以模型恰好保留否定作为唯一保护。 |
