# 多设备预览与逐条模拟下发（首版说明）

本日后续已增加同设备及多设备不同动作，见[后续扩展说明](同设备与多设备不同动作_20261109.md)。以下保留首版范围及验证记录。

首页选择“变电站设备运维”，勾选模拟模式，业务参数保持`{}`，输入：

> 启动主变1和主变2的冷却风机

点击“分析问题”，再进入“操作建议”。两台风机分别显示目标、协议、动作、参数及是否被阻止；详细载荷和联锁轨迹可以展开。点击“模拟下发本条”只执行所选设备。

执行一条后，尚未执行的可用条目会依据最新状态重新预览并重新校验联锁，用户需再次核对并点击对应按钮。不会自动执行下一条，也不会绕过状态版本检查。单条已处理命令不允许再次点击；后端仍保留幂等结果。

## 首版范围

- 支持多个明确设备的同一种独立动作；带数值参数时，本版使用共同且一致的目标参数。
- 每台独立校验：一台被阻止时，其他台的预览仍可查看，不伪装整批成功。
- 未知设备、目标冲突、否定和附加条件不会生成批次；不同动作或先后依赖的流程需拆分。
- 输入变化会使整批旧按钮失效；执行结果未确认时禁用其余按钮并提示查询状态、重新分析。
- 沿用各业务场景独立身份和自动汇总共享状态；单设备响应及下发方式保持兼容。

## 接口

`/analyze`的data增加simulation_batch：status、generated_count、blocked_count、items；每项包含device_id、display_name、action、action_name、parameters和独立preview。批次的candidate_instruction为空，防止旧客户端只执行第一台。

`/generate-instruction`同时返回simulation_batch和simulation_session_id。逐条执行仍使用已有会话preview/execute接口；本版没有增加整批自动下发接口。

## 验证

161项相关Python回归通过，其中前端测试入口运行了10项Node测试。真实Chromium、完整条款库在线后台及真实DeepSeek验证了两设备预览、逐条执行、第一条执行后第二条重新预览、共享会话状态更新、混合编号名称，以及否定、顺序依赖、未知目标的阻断。执行结果均为本地虚拟设备反馈。
