# 用户提问驱动的工具审阅与完善建议

审阅日期：2026-11-03。代码基准：`b1ea1ab0708ce9d43c62c585d96a10874a6eb003`。

本轮检查用户实际问法、后端响应及前端使用流程。产品源码、配置和标准数据未修改；本文件为本地新增审阅交付物，复现材料放在忽略目录 `.tmp`。未提交、未上传。

## 结论

当前工具能完成明确设备的状态查询、可用动作查询和单动作模拟预览，但在用户自然表达、设备选择、条件保留和结果展示之间存在断点。应先修正会改变用户原意或显示旧结果的问题，再增加问法、示例和数据。仅增加条款数量不能解决这些问题。

下列操作问题均指模拟预览或模拟界面；目前仍需用户明确点击模拟下发，不能表述为系统已经自动操作真实设备。

## 1. 优先修正：同一句话的意思不能在处理途中改变

### 1.1 否定、询问被当成操作请求

- 用户问：“禁止启动主变1的冷却风机”“主变1的冷却风机启动了吗？”
- 实际：两者均生成风机1的启动预览，可进入模拟下发；“不要启动”则正确保留为无指令回答。
- 根因：`src/standard_knowledge_service_v2/application/simulation_query.py:114`只排除有限词汇，没有统一使用意图判断；通用分类器的否定保护没有覆盖全部入口。
- 另一入口：受控建议模型把“根据标准，禁止启动模拟风机1”改写成肯定建议后，`application/grounded_advice.py:107`附近的原请求检查只覆盖取消生成，仍可形成启动预览。该验证使用人工构造响应，不代表实际在线模型必然这样输出。
- 验收：禁止、不应、不得、不要、取消及“启动了吗/能否启动/是否启动”不得仅凭动作词形成操作；所有创建预览的入口都必须保留原问题的限制。

### 1.2 条件被丢弃，顺序动作被压成一项

- 用户问：“如果主变1的绕组热点温升超过80K，就启动主变1的冷却风机。”当前快照热点为50K，实际仍生成启动预览，候选中没有该条件。
- 用户问：“先停止主变1的冷却风机，再启动它。”实际只生成启动。
- 根因：`simulation_query.py:66-71`按固定列表取第一个动作；`:114-129`没有将用户条件或动作序列传给预览。
- 修正方向：当前单动作入口先明确阻止尚不支持的条件规则和动作序列，并解释需要拆分；若以后支持条件操作，条件必须随预览保存，且执行前重新读取同一共享世界的状态验证。不能只在回答文字中保留条件。

### 1.3 未知编号、并列对象及正文参数冲突

| 用户输入 | 当前表现 | 期望 |
| --- | --- | --- |
| 主变99当前状态如何？ | 回答主变1、2状态，没有说明99未登记 | 提示编号未登记，保留用户指定名称 |
| 比较主变1和断路器2的当前状态 | 返回断路器1、2，遗漏主变1 | 保留两个并列对象；只有明确所属短语才转换为附属设备 |
| 启动主变2的冷却风机，业务参数却指定主变1 | 生成风机1启动 | 指出目标冲突并要求明确 |
| 正文要求启动，业务参数action为stop | 生成停止 | 指出动作冲突，不能静默覆盖 |

根因在 `simulation_query.py:18-58,119`：显式参数优先后不再核对正文；关系词在全句生效；名称匹配失败后只按设备类型扩展全部设备。

验收要同时覆盖合法唯一目标、泛指“所有主变”、未知编号、跨场景同类型设备、明确所属短语和并列短语。具体场景仍使用独立身份，自动汇总引用原有编号及同一份状态。

### 1.4 数值被改成了另一个数

- “将主变1的调压装置设定为8.5档”实际生成5档；“-1档”实际生成1档。
- 18档正确被阻止，9档正常进入预览，因此问题发生在解析阶段，而非缺少后端范围校验。
- 根因：`simulation_query.py:125`仅提取紧贴“档”的无符号整数，丢失小数前半部分或负号。
- 验收：完整读取数值后验证整数性、范围及正文/结构化参数一致性；非法输入应说明原因，不得截取成合法值。

## 2. 依据可信：回答必须遵守用户指定的来源范围

### 2.1 标准编号、版本限制没有贯穿所有路径

- 合成对照中，明确请求2026版，主变状态评估仍返回2010版证据并给出normal。`application/real_clause_assessment.py:55-57`没有传递标准编号、版本、章条过滤；`:67-73`可选设备绑定条款也没有按请求范围复核。
- 合成对照中，仅在问题文字里写“按DL/T 9000-2026”，通用知识问答仍可能采用同为2026年的另一标准。`analysis_pipeline.py:103-111`主要从结构化参数传标准编号，而文本解析出的标准引用只用于取版次，没有同等的编号硬约束。
- “比较DL/T 9000-2010和DL/T 9000-2026”只召回2010、引用单条原文并标记answered。单版本过滤不能代替多版本对比，应分别检索两侧再逐项回答，缺任何一侧都需说明。
- `retrieval_engine/lunwen_adapter.py:141-155`从标准编号任意位置寻找四位年份，合成的`GB/T 2026-2016`会误通过2026版过滤。应优先明确版次字段，仅在缺失时解析版次后缀，不能把流水编号当年份。

以上合成编号用于验证过滤逻辑，不是真实标准或适用性判断。

### 2.2 当前主变演示依据缺少完整标准身份

用户可能追问：“依据哪个标准、哪个版本、哪一条？”

本轮加载真实的 `datasets/lunwen/verified_json/json/11_clause2.json` 后，返回证据的 `standard_id` 为“未标注标准”、`version`为空，能够定位2017.xlsx的Sheet1第11行及来源原文。Excel年份不能据此认定为标准版次，内部clause_id也不能代替正式章条号。

数据补充应优先核实该演示条款的标准编号、名称、版次、正式章条、完整适用条件及原始来源，保留原文和审查状态。核实前应明确标示“来源记录可追溯，标准身份待核验”，不得补造标准名称或把三个温升比对包装成设备整体健康结论。

### 2.3 一致性比较的单位和边界有错误

本轮独立复跑底层比较，确认：100ms与0.1s被判冲突（ms匹配为m）；“小于1000V”和“不小于1000V”被判相容（开闭边界丢失）；两个约束中一项冲突可被另一项相同约束的平均分掩盖。

对应 `consistency_evaluation/numeric_constraints.py:33,46-61,77`和`features.py:54`。这些错误位于共享特征层，会影响后续比较与候选判断；本轮不把底层结果冒充为完整在线模型问答结果。

修正要包括最长单位优先、单位边界、同参数约束配对、严格不等式端点及独立硬冲突标志。任何明确矛盾都不应被相似度平均分抵消。

### 2.4 检索相关和引用存在仍不足以保证答案正确

- 用户问“断路器温升限值是多少？”，在缺少断路器来源、只有“电缆温升不大于65K”的合成小库中，实际返回answered和电缆要求，warnings为空。`scenarios/context_builder.py:34`没有从已提取的设备实体补全设备类型，`validation/applicability_validator.py:15`因类型为空跳过核对。应保留提问对象并核验条款适用范围；缺少适用来源时说明不足，不能用其他设备的相似限值代答。
- 在受控建议响应中，引用的确是65K来源规则，摘要却写“限值999K，当前70K符合要求”。系统仍接受摘要，并放到直接回答首句。`grounded_advice.py:143-160`检查结构及引用ID，`:98`前置摘要，没有对摘要数值、单位及结论做来源比对。应在显示前核对可验证事实，失败时保留来源原文并说明建议未通过校验。

两项均已在当前源码中复现；第二项使用人工构造的错误模型响应，只证明防护缺口，未观察或测量外部模型的实际幻觉率。

## 3. 显示可信：回答、操作反馈和设备状态应属于同一次请求

| 用户过程 | 已复现的问题 | 修正及验收 |
| --- | --- | --- |
| 第一问成功，第二问参数错误或请求失败，再切页签 | 第一问旧答案复活，状态恢复“查询完成”，输入框仍是第二问 | 结果绑定提交内容；新请求失败后不能把旧答案当本次结果 |
| 模拟下发完成后，先前的慢状态请求才返回 | 后台风机运行，侧栏被旧快照覆盖为停止 | 同会话按读取序号和状态版本接受快照，拒绝旧版本 |
| 点击模拟下发，响应途中连接丢失，切到回答页 | 操作页提示“请求未确认”，回答页仍说“尚未执行” | 各入口统一显示未确认，提供刷新状态/查询该命令结果；不能直接重新操作 |
| 变电场景高温后，切自动识别并设normal | 顶层已为normal导致不发工况请求，子场景仍高温 | 汇总比较各子场景工况；相同具体工况的重复查询仍不能重置执行状态 |

对应 `frontend/index.html:28,39-56`，`frontend/original-simulation.js:85-91,101-124,170-171`。前端复现采用受控DOM和延迟API响应，未连接实际设备；浏览器兼容性未在本轮验收。

## 4. 使用完善：先让常见问法有明确、可理解的结果

以下应区分为明确入口缺陷和待补能力，避免把“尚未支持”说成“已经修好”。

### 已有能力的入口缺陷

- 配置自带示例“主变1现在有什么数据？”未命中事实入口；空条款库返回uncertain，有真实条款时还可能转为原文回答，而非设备数据。
- “开启主变1的冷却风机”没有进入模拟操作分支，尽管内部动作解析已支持“开启”。入口词表与内部动作词表应共用。
- `/knowledge/questions`宣传的主变1异常示例未设置高温工况，按返回参数直接运行却是normal；断路器示例宣称应uncertain，实际按新事实查询能力返回answered。示例期望必须随当前行为更新，并包含可复现的初始状态。

### 待补的产品能力

- **数据来源与假设工况**：问句给热点温升95K，当前实现仍读取模拟快照50K并返回该快照normal。回答确实列出所用模拟数值，但没有直接说明“你给的95K未参与评估”。建议明确区分“查当前模拟状态”和“按输入工况做假设分析”，冲突时说明或请用户选择；假设分析不应暗中修改共享模拟状态。
- **续问**：“这台风机当前状态如何？”即使API上下文此前唯一指向风机1，事实分支仍返回两台风机；首页也未发送对话历史。若实现续问，应保存唯一目标及当前场景，上下文不唯一时要求补充，不能猜测。
- **文字场景**：自动识别时用户文字指定“电网故障隔离场景的断路器”，当前会按类型返回跨场景设备。应解析明确范围，并检测其与下拉框选择是否冲突。
- **输入引导**：保留现有布局，增加实际可运行的问题示例、设备选择、工况选择和参数说明；工况或档位等常用输入不应要求普通使用者先手写JSON。
- **答案组织**：按“本次理解的设备与目的→使用的数据及来源→结论与适用边界→引用→可进行的下一步”组织。信息不足应列明缺哪个字段、用户如何补，不能只给“证据不足”。

## 5. 建议实施顺序与验收门槛

1. **先修正原意改变**：所有入口统一否定/疑问/条件/多动作判断；修正目标解析、参数冲突和档位数值。验收要求是错误或含糊意图不产生错误的模拟候选，同时保留明确单动作正常路径。
2. **再修正来源和结果可信度**：标准身份与版本贯穿检索和绑定召回；修正数值约束；失败结果、未确认下发、快照版本和工况切换统一。验收包括失败/延迟/断开场景，不能只看成功流程。
3. **补使用能力和数据**：明确假设工况与当前快照的边界，再做续问、文字场景、问题示例及结构化表单。首先补齐主变演示条款的真实身份和适用条件，再扩展其他设备。

每个场景的数据包建议同时提交：设备实例及所属场景、别名、动作和联锁、初始/故障/恢复工况、协议映射、来源原文及审查记录，以及一组用户问句和预期结果。每个问句至少记录目的、目标、输入事实与单位/来源、缺失项、允许的证据范围、期望回答、是否允许预览、执行前后状态和反馈。这样补充数据时可以直接验证对用户有没有用。

## 6. 本轮验证记录

- 两组不重叠现有专项测试：29项、38项，合计67项通过；不是完整测试套件或产品无问题的证明。
- 新增22个针对易错表达的用户问题，通过内存FastAPI `/analyze`验证：9个符合本次验收预期，13个未达到。故意覆盖边界，不代表随机用户问题的总体准确率。
- 这22个问题均未改变设备快照；未调用execute。使用一个真实条款JSON、RawTextFallback及不加载权重的一致性服务，无外部模型调用。
