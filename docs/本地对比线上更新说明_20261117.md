## 3. 完整报文功能

### Modbus TCP

- 生成完整MBAP头和PDU，包含事务号、长度、单元标识、功能码、点位地址及编码后的值。
- 当前已登记动作覆盖05写单线圈、06写单寄存器、16（0x10）写多寄存器；另生成读取独立反馈点的请求。
- 模板与报文共用编码逻辑，支持布尔、有符号及无符号16/32位整数、float32，并校验倍率、字节序、字序及寄存器跨度。
- 修正原有uint16/单寄存器限制对小数和32位数值动作的阻碍。

### IEC61850 / MMS

- 补齐COTP连接、会话层、表示层、ACSE关联和MMS初始化请求。
- 覆盖直接普通、直接增强、先选择后操作普通、先选择后操作增强四种控制模型。
- 按对象配置生成选择、操作、独立读回，以及适用的取消和正常释放分支。
- 完整编码控制值、来源、控制序号、时间、Test、Check及对象声明需要的计划操作时间。
- 每个阶段记录所需前置响应；增强控制要求最终完成反馈，不能仅凭写入确认判定成功。

### 导出及操作结果核验

ZIP包含清单和各阶段二进制请求。清单记录设备、动作、参数、会话和配置版本、阶段依赖、响应要求、输入来源及反馈期望。

例如当前8档、要求升一档，命令码可以是1，但期望读回为9；两者分别保存。IEC使用Test=true时，反馈期望保持物理状态不变，并另列实际执行时的预期变化。

报文生成由程序编码，不增加模型调用。生成和下载不会执行设备动作。

## 5. 补充参数的使用规则

优先级为：**提问明确给出的当前值或业务参数补充值，优先于模拟预设。** 提问与业务参数之间没有默认高低顺序，二者矛盾时需要澄清。

- 当前状态、测量值：字段、类型、设备身份和单位匹配后更新当前模拟会话。
- 动作目标：沿用`action_parameters`，参数名和单位与动作模板一致。
- 历史记录、假设、参考阈值、不等式：保留为背景或执行条件，不推算成精确当前值，也不当成真实标准定值。
- 输入与模拟值不同：显示原值、采用值、来源和冲突提醒，按采用后的状态继续校验。
- 用户输入彼此冲突：在状态提交前整体阻止，避免部分写入。
- 状态更新：使旧指令和旧报文预览失效；重置会话可恢复预设。明确模拟执行改变字段后，旧补充值不再标为该字段的当前来源。

旧预览失效指服务端拒绝继续使用旧版本生成报文或模拟下发；已下载的文件不会自动删除，后续使用前仍须重新核验状态和会话条件。

业务参数补充设备状态示例：

```json
{
  "device_facts": {
    "SIM-IEC-FAN-01": {
      "device_fault": 0,
      "state.running": false
    }
  }
}
```

业务参数补充单条动作目标示例：

```json
{
  "action_parameters": {
    "target_power_mw": 60
  }
}
```

实际效果示例：

| 场景 | 本次更新后的处理结果 |
|---|---|
| 模拟回降定值80MW，用户明确要求60MW | 采用60MW，提示与模拟定值不同；方向、范围和许可仍须通过 |
| 原模拟故障标志为1，用户补充为0 | 采用0；其余条件满足时可以生成 |
| 原模拟故障标志为0，用户补充为1后要求启动 | 采用1并提示冲突；故障联锁仍阻止启动 |
| 提问60MW、业务参数70MW | 提示用户输入冲突，不生成指令，也不部分写入附带状态 |
| 提问电流0.7A，业务参数700mA | 统一单位后视为一致，不因小数误差误报输入冲突；分闸等动作仍按实际条件校验 |

## 8. 当前边界与发布状态

当前实现是模拟环境中的完整客户端应用协议请求生成。真实设备仍需实际地址、点表、控制模型和安全配置联调；IEC后续阶段必须核验真实对端响应，必要时按协商结果重新编码，不能把所有请求无条件连发。

IP/TCP头由通信客户端和操作系统处理。当前IEC范围为MMS控制与读回，不代表覆盖GOOSE、SV或全部IEC61850服务。自然语言仍由模型理解，已测场景通过不等于任意问法都能正确处理。

本次没有新增真实标准条款，也没有开启真实设备下发。本批提交仅包含功能代码、验证脚本、README入口及本说明一份更新文档；运行日志、审计数据、临时依赖和其他本地草稿不随本次发布上传。真实设备下发仍关闭。
