## 一、对接目的及预期价值

为验证机器可读标准知识服务在实际业务中的适用性，拟与具有明确标准查询、设备状态判断或业务合规审核需求的单位开展小范围试点。

试点拟围绕一个具体业务问题，建立“业务问题—适用标准—实际数据—规则判定—建议输出—候选指令生成（有依据时）—人工复核”的关联链。预期帮助业务人员缩短查找条款和比对数据的时间，明确判断依据，并识别标准、数据或配置不完整的情况。

本阶段为科研原型适配与验证。当前工具具备条款查询、部分条件校验、操作建议及候选指令生成能力，不承诺已覆盖所有业务、设备和标准。试点输出供人工复核，不替代正式业务审批、现场操作规程或专业结论。

## 二、请先明确一个实际需求场景

请试点单位提供下列场景说明，不要求先整理成机器学习数据集：

| 说明项 | 请提供的内容 |
| --- | --- |
| 实际业务问题 | 谁在什么业务环节需要判断什么，例如“温升试验数据是否符合适用条款”，而非仅写“建设智能运维” |
| 现行处理方式及痛点 | 查阅哪些文件、使用哪些系统、由谁判断、主要耗时及易错环节 |
| 适用对象与范围 | 设备或业务对象类型、工况、场景边界，以及本次不处理的事项 |
| 判断依据 | 当前实际使用且经单位确认适用的标准、企业制度、规程或技术文件 |
| 输入与期望输出 | 能提供哪些数据；希望得到条款引用、符合性判断、检查建议还是候选指令 |
| 人工确认机制 | 哪类专业人员能够复核适用条款、样本结论及建议是否合理 |
| 评价方式 | 拟比较的人工基线、典型错误、准确性和效率指标；具体指标双方确认 |

建议先选“对象明确、依据清楚、数据可取得、有人能够复核”的场景，不同时承诺覆盖多个专业领域。

针对首批建议场景，待验证问题可表述为：“该设备本次所选试验项目的结果是否符合适用条款？依据是什么，哪些数据或条件缺失，需要怎样复核？”具体试验项目、设备类型和标准版本由单位专业人员确定。

温升试验符合性、在运状态评价与整台设备健康结论不是同一件事；单项指标未越限不能直接证明设备整体正常，越限也不自动证明应生成跳闸或停机指令。油色谱、绝缘电阻、温升等可作为待选择项目，不能假定同一标准及限值适用于全部设备和工况。

## 三、数据需求清单

### 3.1 首批建议场景的成套数据

请单位从下表中明确可提供范围。涉及现场数据的内容须经单位授权，建议优先使用脱敏历史资料，不要求实时系统接入。

| 数据包 | 请提供的资料 | 最小关联与说明 |
| --- | --- | --- |
| A. 适用依据 | 本单位实际使用的变压器试验/评价标准、企业规程和相关条款、表格、例外说明 | 完整名称编号/内部文件ID、版本、有效性、适用设备及试验条件；不能只给无上下文的阈值 |
| B. 设备台账 | 所选设备的脱敏ID、设备类别/型号、额定容量、电压、冷却方式及影响判定的配置 | 仅采集该判定需要的属性，缺失项注明；不预设所有设备都是同一类型或冷却方式 |
| C. 实际记录 | 专业人员选定的油色谱、电气试验、温升或相关监测记录 | 样本ID、设备ID、时间、项目、原始值、单位、工况、数据来源与质量状态；计算变化率时提供必要的历史点及时间间隔 |
| D. 关联历史 | 与所选判定有关的缺陷、检修、复测及相关历史记录 | 通过设备ID和时间关联；非必要信息不交付，不能取得时说明对判定的影响 |
| E. 人工参考结论 | 与C对应的原试验报告、人工评价或专业复核意见 | 结论、条款依据、适用性说明、缺失条件、复核状态；仅验证单项时不要求编造综合等级 |
| F. 数据口径 | 台账/试验/监测中的字段定义、单位和倍率、设备编码对应、缺失值、采样及统计说明 | 使用同一脱敏设备ID；单位换算和推导方式说明；项目组可草拟条款映射，交专业人员确认 |
| G. 业务流程 | 试验接收、数据核对、条款比对、评价复核、报告生成等实际步骤 | 当前角色、处理方式、典型错误、可用于比较的耗时及期望输出；暂无BPMN文件可用文字描述 |
| H. 候选指令专项资料 | 如确需验证指令，另行提供明确动作条款、生成前置条件/联锁、参数来源及脱敏协议点表 | 本批状态/试验判定可以不提供；没有动作依据就不生成设备指令，不能用维护建议或限值条款替代动作依据 |

A、B、C、E、F、G为首批场景核对的核心内容；D按实际判定需要提供，H仅在双方确认候选指令验证范围后提供。数据项的最终必需性由所选条款和专业人员确认。

一组“完整样例”是一次具体试验或业务判定及其关联资料，不是一个孤立测量值；同一设备可以有多组不同时间的样例。若验证温升，已有报告中的温升值应说明测量口径；需要由温度计算温差时，应提供对应测点和环境温度及时间/工况，不能将绝对温度直接套用温升限值。

| 实际输入数据 | 对象ID、记录/样本ID、参数名称、值、单位、时间或业务发生日期、工况、来源和质量标记 | 首批必需；历史运行记录、试验记录或审核材料均可，不要求开放实时系统 |
| 专业判定样例 | 对应样本ID、人工结论、判定依据、适用条款、建议及复核状态 | 首批必需；用于验证，未经确认的结论须标记，不能作为确定的正确答案 |
| 字段与编码说明 | 字段含义、数据类型、单位、倍率、枚举、缺失值含义、采样/统计口径、时间区间 | 首批必需；现有字典即可，暂无字典时由双方共同整理 |

| 动作与生成条件依据 | 经确认可建议的动作、适用对象、触发条件、前置条件/联锁、参数来源、例外与禁止动作 | 仅在验证候选指令时需要；仅有技术限值不能自动作为设备动作依据 |
| 脱敏协议资料 | 协议类型及版本、脱敏或模拟逻辑对象/点位与寄存器含义、数据类型、倍率、候选字段样例和资料版本 | 仅在验证协议候选字段时需要；可使用厂商资料节选或模拟点表 |
| 指令生成测试样例 | 输入问题、只读状态快照、触发条件、参数、期望候选字段与不应生成的原因 | 指令专项按需提供；覆盖正常、边界、缺失数据和联锁不满足，不需要执行结果 |
| 反馈与评价记录 | 实际业务问题、结果是否有用、错误类别、人工修订、原流程耗时及核对结果 | 试点过程中逐步形成，支持评估和迭代 |

优先提供与选定场景直接相关的数据，不以“全部电力标准”“全部设备运行数据”为首批交付要求。

## 四、首批最小数据包与交付形式

### 4.1 首批建议内容

1. 一份明确的场景说明及若干实际业务问题。
2. 场景实际使用的适用依据，以及相关条款、表格和附录。
3. 与业务问题对应的少量对象资料和实际输入记录。
4. 对上述记录的专业判定、依据与复核状态。
5. 字段字典、数据来源说明、交付目录及使用授权信息。

数量建议为10—20组完整样例，最终以可取得数据和双方确认范围为准，不是任务书规定的最低数量或验收规模。尽量覆盖正常、异常、边界与信息不足情况；缺少某类真实样本时应明确说明。项目组可补充人工构造测试，但必须与真实样本分开标记。

首批样例主要用于确认可用性和发现缺口，不能据此宣称系统总体准确率。后续需留出独立、未经开发调参使用的评测样本，并确定样本量和评价方法。

### 4.2 推荐交付形式

- 场景与依据文件：现有Word、PDF、Excel、文本或受控文件位置即可。
- 台账、测量及判定样例：Excel或CSV，每行一条记录，保留表头和单位说明。
- 协议资料：已有协议手册、脱敏点表或合法样例，不要求对方编写指令模板。
- 交付清单：文件名、内容范围、来源系统/部门、版本/数据时间区间、责任角色、保密限制及授权范围。

不要求试点单位直接提供JSON、知识图谱、向量库、模型权重或训练好的大模型；转换、数据映射草拟及工具适配由项目组承担。

### 4.3 样例记录的关联要求

每组样例至少能够对应：

`样本ID → 对象ID → 实际输入数据 → 适用依据及条款 → 人工结论与复核状态`

脱敏后的对象ID应在不同文件中保持一致。原始标准编号和条款编号保留；没有正式标准编号的企业制度使用内部文件ID，不造编号。不适用项标记“不适用”，未知或缺失值不得用0代替。

温度、温升、功率、时间等必须注明单位；统计量还需注明时间窗口。已清洗或推导的值应说明方法，并保留允许交付的原始值或追溯信息，不能把插补值当成实际测量值。

## 五、数据使用与安全边界

1. 提供单位先确认数据来源、使用权限、保密级别及可交付范围；不便导出的资料可协商在单位环境内处理或采用脱敏、受控查询方式。
2. 人员、客户、生产位置及其他敏感信息按单位要求脱敏；保留必要的稳定关联ID。不索取生产系统密码、API密钥、远程控制权限或开放控制端口。
3. 默认仅在双方批准的项目环境中用于该试点，不上传GitHub等外部代码托管或云存储平台（包括私有仓库），不发送至外部大模型，不转交第三方。确需改变存放位置、调用外部服务或公开成果时，应另行取得明确的书面授权。
4. 留存期限、允许访问人员、是否允许用于模型训练、是否允许形成衍生数据、成果公开范围、到期返还/删除方式及验证方法，均由双方书面确认；试点授权不自动等于训练或公开授权。
5. 功能验证终点为建议与候选指令生成，只核对条款来源、生成条件、参数和协议字段。设备状态作为只读输入；无动作依据、缺少数据或无法可靠判定时，可以只返回建议或“不确定”。

本文不是已经获得的数据授权；授权未确认的资料不得进入处理流程。

## 六、双方工作分工

| 参与方 | 主要工作 |
| --- | --- |
| 试点单位业务及专业人员 | 明确实际需求、适用依据与工况；提供现有资料；复核条款映射、样本结论和建议合理性 |
| 试点单位数据/系统及安全人员 | 确认可提供字段、导出方式、脱敏、访问和使用范围；参与交付与授权确认 |
| 项目组 | 数据整理与结构化、缺口分析、条款—数据关联、规则和模板适配、工具测试、错误分析及试点报告 |
| 双方共同 | 确认场景边界、交付批次、验收口径、评测集、时间安排、成果使用和问题处理方式 |

项目组不以自动抽取替代专业人员的适用性审查，也不要求单位仅为满足数量而补造样本。

## 七、分阶段实施与交付成果

| 阶段 | 工作 | 项目组拟交付 |
| --- | --- | --- |
| 场景确认 | 确认需求、边界、数据可得性、授权及评价方式 | 场景确认表与首批数据清单 |
| 小样本核对 | 核查字段、单位、来源和记录关联 | 数据缺口清单、关联映射草案 |
| 原型适配 | 在批准环境中处理条款和数据，形成判断与建议，按需生成候选字段 | 演示结果、依据与校验明细、适配限制 |
| 专业复核与评测 | 专业人员核对结果，以独立样本评价，记录错误和效率 | 评测结果、问题分类及改进建议 |
| 试点总结 | 确认可用范围、未完成事项及后续扩展条件 | 试点验证报告及双方认可的数据/规则版本 |

具体交付日期和时限另行确认。拟交付不等于已实现功能承诺，原型不能支持的需求应在场景确认阶段明确。

## 八、评价与数据接收口径

数据接收主要检查：文件可读、来源与权限已确认、字段与单位可解释、样本与对象及依据可关联、缺失和质量状态明确。数据不完整时可形成补充清单或缩小试点范围，不简单以文件数量认定完成。

业务评价建议包括：条款检索是否正确、适用性与状态判断是否合理、建议是否有依据、需要指令的样例是否正确转换、不应生成的样例是否可靠阻止、失败原因是否可解释，以及相对于现行方法的时间变化。

适用指标、统计口径、目标值和测试规模由双方在评测前确认。论文指标、单次演示和程序测试通过不能代替试点业务效果评价。

## 附：请试点单位反馈的确认事项

- 拟试点单位/部门、首个场景及专业联系人：待确认。
- 当前问题、适用依据、可提供数据及暂时不能提供的数据：待确认。
- 数据获取方式、脱敏规则、处理环境和使用授权：待确认。
- 首批样例范围、复核人员及交付时间：待确认。
- 预期输出、不涉及的业务事项及评价方式：待确认。

建议先召开一次场景与数据核对沟通，再按确认范围下发正式数据清单，避免首批要求过宽而无法交付。
