# 10 kV馈线断路器指令模板

2026-10-26补充，2026-11-01整理纳入本次发布。以馈线断路器为设备场景，新增IEC61850和Modbus各一台模拟设备、各三项动作。旧生成服务及原模板管理页由17台设备、41项动作扩充为19台设备、47项动作。新通用目录另有25台/61项的聚合口径，见 [本次更新说明](本次更新说明_20261101.md)。

## 使用入口

重启后端并刷新前端，从首页进入“指令模板管理”，搜索“馈线断路器”，可查看6条新增模板的条件、联锁、点位和来源状态。设备ID分别为`SIM-IEC-FEEDER-BREAKER-01`及`SIM-MB-FEEDER-BREAKER-01`，场景为`grid_fault_isolation`。

## 指令与条件

| 指令 | 动作名 | 触发条件 | 附加模拟联锁 | 生成值 |
| --- | --- | --- | --- | --- |
| 分闸 | trip | trip_permission == 1 | 远方控制使能、控制电源可用、断路器已合、分闸回路正常 | false |
| 合闸 | close | close_permission == 1 | 远方控制使能、控制电源可用、断路器已分、弹簧已储能、接地开关已分、手车工作位置、保护未闭锁、合闸回路正常、同期或无压等外部合闸许可成立 | true |
| 告警标记 | alarm | alarm_required == 1 | 不依赖分合闸许可 | true |

合闸的具体字段依次为`remote_control_enabled=1`、`control_power_available=1`、`breaker_closed=0`、`spring_charged=1`、`earth_switch_open=1`、`truck_in_service=1`、`protection_lockout=0`、`closing_circuit_healthy=1`、`closing_sync_permitted=1`。最后一项由调用者显式提供，本工具不计算同期或无压判据。

分闸不复用合闸的储能、接地开关或同期许可条件。此处是远方操作的简化软件样例，不描述保护自动跳闸回路。告警只表示布尔标记载荷，不表示真实遥信采集、告警上送或复归。

## 协议点位（全部虚构）

| 协议 | 分闸/合闸 | 告警标记 | 说明 |
| --- | --- | --- | --- |
| IEC61850 | SIM_FEEDER/CTRL/XCBR1.Pos | SIM_FEEDER/CTRL/GGIO1.SPCSO1 | 沿用现有Operate服务字段示意，ctlVal分别为false/true；不实现完整IEC服务交互 |
| Modbus | 从站20，线圈地址600 | 从站20，线圈地址601 | 地址为PDU中的零基地址；功能码05，分闸编码0000，合闸及告警编码FF00 |

Modbus分闸PDU为`05 02 58 00 00`，合闸为`05 02 58 ff 00`，告警为`05 02 59 ff 00`。PDU不含从站地址、RTU校验或TCP封装，不能作为完整通信报文使用。

## 最小实验

在项目根目录启动Python（`.venv\Scripts\python.exe`），执行：

```python
from copy import deepcopy
from standard_knowledge_service_v2.instruction_engine.simulation import SimulationInstructionService

service = SimulationInstructionService()
device_id = "SIM-MB-FEEDER-BREAKER-01"
facts = deepcopy(service.devices[device_id]["runtime_facts"])
before = deepcopy(service.states)

trip = service.generate(device_id, "trip", facts)
assert trip.payload["pdu_hex"] == "05 02 58 00 00"

# 只生成指令不会改变状态。测试合闸时须显式提供“已分闸”事实。
facts["breaker_closed"] = 0
close = service.generate(device_id, "close", facts)
assert close.payload["pdu_hex"] == "05 02 58 ff 00"

facts["earth_switch_open"] = 0
blocked = service.generate(device_id, "close", facts)
assert not blocked.payload

del facts["earth_switch_open"]
uncertain = service.generate(device_id, "close", facts)
assert not uncertain.payload

alarm = service.generate(device_id, "alarm", {"alarm_required": 1})
assert alarm.payload["pdu_hex"] == "05 02 59 ff 00"
assert service.states == before
assert all(not c.dispatch_allowed for c in (trip, close, blocked, uncertain, alarm))
```

6条完整通过样例已追加到`configs/instruction_template_examples_supplement.json`，设备和模板位于`configs/simulation_devices_supplement.json`，沿用原有自动加载机制。

## 来源与适用范围

所有新增模板的`source_rule_ids`为空，`source_scope`为历史标记`synthetic_test_fixture_pending_source_binding`。该标记继续兼容读取，不再表示必须绑定条款后才能转换。这里的10 kV只是设备场景标签，不代表进行了电压等级校核；联锁是人工编制的测试条件，不宣称满足任何具体标准或厂家规程。条款引用及厂家点表仍需按实际用途核验，详见 [动态转换说明](指令转换取消固定绑定_20261031.md)。

以上旧生成服务实验的所有候选保持`dispatch_allowed=false`，不连接真实设备，也不改变模拟设备状态。默认事实为“已合闸”，因此默认分闸样例可生成；合闸样例需显式提供`breaker_closed=0`，缺失或不满足任一条件时不生成载荷。新会话的明确模拟执行是另一入口，见 [模拟使用与配置](变电站模拟工作台.md)。
