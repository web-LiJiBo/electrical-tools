# 操作语义复核与查询完整性（2026-11-12）

本次以main的fe803d29为基线。用户于2026-11-12明确授权将本次代码和更新文档同步到main。此前版本通过已覆盖测试后，再次审阅发现反向动作缺核验、纯查询漏项和“再次”误判，本次补齐对应行为及异常输入测试。

## 处理流程与调用次数

| 请求 | 正常模型调用次数 |
|---|---:|
| 当前状态/能力查询 | 1 |
| 单项或多项模拟操作 | 2：整句理解＋整批语义复核 |
| 有条款来源的标准分析 | 2：理解＋检索后建议 |
| 操作与标准混合 | 2：理解＋合并复核与建议 |
| 模拟确认下发、重新预览、模板编辑 | 不新增模型调用 |

操作数量不改变复核调用次数。首轮理解失败时停止；复核接口异常、输出不完整或被截断时停止，不回退硬分句、不自动第三次调用。条款无来源时不调用建议模型；涉及操作仍只进行一次单独复核。

## 修复内容

- 二阶段独立请求读取完整用户原话、设备目录及首轮清单，逐项核对动作方向、设备、参数、否定、条件、顺序和遗漏。复核结果必须恰好回显所有操作，不能修改设备/动作/参数后批准；异常字段、重复JSON键、缺项、非有限数和布尔冒充数值均被拒绝。
- 原始操作清单对应的预览和命令ID均在复核通过后生成。组合条款子请求强制为知识分析，不因原文片段包含“启动”等动词先生成候选指令。复核失败不自动生成替代操作，不改变设备状态。
- 纯查询执行目录目标及原文覆盖核验；查询两台却只列一台时明确澄清，不显示全部已回答。按项保留状态/能力结果，所属主设备描述不误算独立查询对象；同句指代支持明确前项，多个候选保持歧义。
- “再次/再一次启动”不再因单字“再”被阻断；真正的结构化顺序、否定、条件仍阻断。保留明确条件表达的保护，不丢条件生成无条件预览。
- 混合事实/条款问题保留各自结果，条款部分不足时整体partial，不掩盖未完成部分。
- 页面处理进度新增操作语义复核状态与原因，异常信息不回显API密钥或接口错误正文。

## 验证与边界

新增受控模型错误输出、二次接口异常、批量调用次数、合并第二阶段、无来源不额外调用、并发隔离、原文片段覆盖整句等回归。真实API使用本会话已经授权的同一组六组模拟设备问法；只做理解与预览，不执行。

语义复核仍依赖模型，不能视为绝对正确的证明。未支持的条件式/顺序式编排仍明确阻断，真实设备下发保持关闭；前端本次由Node脚本测试验证，未声称完成新的真实浏览器视觉验收。
