## 修改后行为

统一流程为：**模型识别完整诉求 → 统一编号、数字、单位及来源 → 程序检查设备、参数与条件 → 独立复核可用操作的语义 → 生成预览和报文**。纯状态查询读取当前快照，标准问题检索已有条款。

- 统一设备别名、所属关系、中文编号、中文数值和单位，修复短名称、嵌套名称及英文空格导致的误拦。完整未知编号和多个候选仍需澄清，不替换成相近设备。
- 模型给出目标数值及原文证据，程序按单位换算并核对来源；区分MW和mW，当前测量值不当作目标。业务参数单独补充目标时不伪造正文数字引用。
- 肯定操作和禁止动作分别处理。“不要停、请启动”可保留启动诉求；同一动作同时被要求与禁止时澄清。
- 分开处理本次当前陈述、历史参考及用户执行前提。历史对话中的状态只保留作参考，按当前快照检查；设备模板的固有联锁继续由程序校验。
- 未知、歧义和缺参数显示正常业务澄清。操作被阻断或需澄清时，保留能够独立回答的事实或标准子问题；只分析限制不取消条件查询。
- 指定测量字段的回答只显示所问值；故障阻断返回具体字段、当前值和要求。条款检索聚焦本题的设备和物理量，减少无关主题及重复说明。
- 保留旧本地分解适配器兼容入口；远程模型仍须返回完整结构。补齐禁止动作及证据字段校验，异常数值安全返回错误说明。

正常单项或多项操作仍调用模型2次，只读查询1次；程序已确定全部操作不能生成时可在1次后结束。报文编码不增加模型调用。身份一致性、范围、真实冲突、联锁、版本和顺序反馈检查继续保留；场景实例仍独立，自动汇总共用同一份状态。

## 保留的边界

模型仍可能识别错误；两轮语义核对及程序校验能减少错误，不保证任意表达始终正确。当前值与目标值的语义角色仍由模型识别，程序核对原文数值、单位、目录与范围。

温升等标准问题仍存在编号、版本、现行性及适用范围缺口，继续在问题清单第15组与附录记录，不扩充真实条款、不补造标准身份。

已由程序确定全部阻断的请求不再请求模型批准；锁和快照版本继续检查。完整报文依旧是模拟配置下的客户端应用协议请求，没有开启真实设备下发，也不代表实机认证。更新已有本地后台后需重新启动工具；本次发布不自动重启原常驻服务。
