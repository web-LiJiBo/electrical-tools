# 统一识别、规范化与程序校验优化

发布日期：2026-11-18。基于仓库main的`05695217`整理，本说明随本批代码发布。问题清单统一放在[正常问题合并清单](正常问题合并清单.md)，按16组展示问题介绍、回答思路，182条来源记录的原始问题放在附录。

## 修改后行为

统一流程为：**模型识别完整诉求 → 统一编号、数字、单位及来源 → 程序检查设备、参数与条件 → 独立复核可用操作的语义 → 生成预览和报文**。纯状态查询读取当前快照，标准问题检索已有条款。

- 统一设备别名、所属关系、中文编号、中文数值和单位，修复短名称、嵌套名称及英文空格导致的误拦。完整未知编号和多个候选仍需澄清，不替换成相近设备。
- 模型给出目标数值及原文证据，程序按单位换算并核对来源；区分MW和mW，当前测量值不当作目标。业务参数单独补充目标时不伪造正文数字引用。
- 肯定操作和禁止动作分别处理。“不要停、请启动”可保留启动诉求；同一动作同时被要求与禁止时澄清。
- 分开处理本次当前陈述、历史参考及用户执行前提。历史对话中的状态只保留作参考，按当前快照检查；设备模板的固有联锁继续由程序校验。
- 未知、歧义和缺参数显示正常业务澄清。操作被阻断或需澄清时，保留能够独立回答的事实或标准子问题；只分析限制不取消条件查询。
- 指定测量字段的回答只显示所问值；故障阻断返回具体字段、当前值和要求。条款检索聚焦本题的设备和物理量，减少无关主题及重复说明。
- 保留旧本地分解适配器兼容入口；远程模型仍须返回完整结构。补齐禁止动作及证据字段校验，异常数值安全返回错误说明。

正常单项或多项操作仍调用模型2次，只读查询1次；程序已确定全部操作不能生成时可在1次后结束。报文编码不增加模型调用。身份一致性、范围、真实冲突、联锁、版本和顺序反馈检查继续保留；场景实例仍独立，自动汇总共用同一份状态。

## 保留的边界

模型仍可能识别错误；两轮语义核对及程序校验能减少错误，不保证任意表达始终正确。当前值与目标值的语义角色仍由模型识别，程序核对原文数值、单位、目录与范围。

温升等标准问题仍存在编号、版本、现行性及适用范围缺口，继续在问题清单第15组与附录记录，不扩充真实条款、不补造标准身份。

已由程序确定全部阻断的请求不再请求模型批准；锁和快照版本继续检查。完整报文依旧是模拟配置下的客户端应用协议请求，没有开启真实设备下发，也不代表实机认证。更新已有本地后台后需重新启动工具；本次发布不自动重启原常驻服务。

## 2026-11-20本地后续优化与Flash切换

本节为11月20日追加的后续变更。此前验收数字仍属于11月18日，不计入本轮结果。

- 默认在线模型改为`deepseek-flash`，显式采用`thinking_mode: disabled`，继续输出JSON并独立复核整批操作。模型名称与模式依据[DeepSeek接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。
- 默认密钥环境变量改为已有的`DEEPSEEK_API_KEY`。启动脚本按配置读取进程、用户、系统变量及`.env`，保留旧`MODEL_API_KEY`兼容，不输出或写入密钥。
- 操作和查询明细作为任务来源，由程序推导摘要和意图；真实API任务不再被旧问句/否定正则重新分流。执行条件按逐项证据保留，表达式仅空格不同也按同一条件处理。
- 按当前场景的设备身份、主附属关系和历史提及处理指代。提供唯一“另一台”的目录依据，同一处提及在操作和查询中共享绑定；来源片段省略设备时，补回包含原设备的最短连续原文，不改写问题。未知编号和真实多候选仍须澄清。
- 当前数值核对原始数字、完整单位及换算结果；设备编号不充当测量值，保留负号、中文数字、科学计数法和SI前缀。中文/英文等价单位按换算核对；单位缺失或被截断导致量纲变化时拒绝更新。中文状态描述仍由模型识别并按目录类型校验。

## 2026-11-20后续：条款指令接入统一流程

首轮模型声明`scenario.instruction_basis`：直接操作、依据条款生成、或只查询。条款路线先按检索相关性保留来源，不再用内部设备动作码精确筛掉自然语言条款，也不在建议形成前生成旧协议候选。

第二轮模型判断来源是否支持动作，并给出原文设备、参数、条件和引用；后台核对引用及适用性，将建议构造成公共操作清单。第三轮模型独立对照用户原文、条款原文及设备目录核对该清单。之后复用直接路线的规范化、设备绑定、参数、用户条件、联锁、版本和协议模板预览。原有建议转换中的独立硬分词/条件拦截和直接调用预览分支已移除。

常规条款生成是3次模型调用，直接生成仍为2次。明确缺项、无可用来源、未提出操作或程序已能判定阻断时提前结束，不为凑次数调用模型。仅要求生成候选、不实际执行，不等于禁止生成。条款支持动作方向、设备配置提供目标时，配置值保留配置来源，不假称条款规定具体定值。

公共预览携带实际采用的条款证据。服务端条款上下文不可由模型或请求JSON注入；会话、状态快照和目录版本在复核后仍会检查。自动选定的会话被绑定到执行请求，避免回到默认会话误报版本变化。目标配置字段单位从明确关联的动作模板继承；只有目录中唯一的设备才能省略展示名的协议括号，同名候选仍不强选。
