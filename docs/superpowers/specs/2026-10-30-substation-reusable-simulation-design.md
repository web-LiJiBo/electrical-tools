# 变电站设备运维与通用设备指令模板设计

> 归档说明（2026-11-01）：以下是原设计及当时的本地授权范围。后续已按用户要求保留原首页和模板管理页，模拟执行接入原“操作建议”；用户也已授权随详细文档一起发布。当前实现和使用以 [本次更新说明](../../本次更新说明_20261101.md) 为准。

日期：2026-10-30。状态：用户已确认并进入本地实施；本次不上传。

## 1. 已确认的目标

用户选择先完善“变电站设备运维”。场景组织设备、关系和模拟运行状态；设备配置和指令模板独立于场景，能够在其他场景复用。利用模拟编号、协议点位及寄存器完成模拟指令下发、状态更新和结果查询。

知识问答、设备状态查询、分析建议及模拟操作分别按问题需要调用，不能要求每个问题都匹配设备动作或预先绑定某条标准。新旧标准库继续共同参与查询。检索到什么依据，就按实际证据说明；缺少依据时说明缺口，不补造标准结论。

实现继续使用现有 Python/FastAPI 后端、JSON 配置和 HTML/JavaScript 页面，不新增数据库、消息中间件或真实设备通信依赖。这是本方案的实现选择。

## 2. 当前代码的实际情况

- 当前本地有 19 台预置模拟设备、47 项写动作；其中包含此前尚未上传的两台馈线断路器和六项动作，应保留。
- `simulation_devices*.json` 将设备实例、协议地址、动作及 `scenario` 放在一起；`TemplateLibrary.find()` 要求场景一致，影响跨场景复用。
- `SimulationInstructionService.generate()` 只生成协议字段，不修改设备状态；API 没有模拟执行入口。现有 `generation_only` 测试明确固定了这一行为。
- 检索后建议链要求动作条款与模板预先绑定；`real_clause_assessment.py` 的状态判断又依赖变压器及固定的 `assessment_clause_id`，不能覆盖所有设备状态问题。
- 普通知识查询已经允许缺少 `rules[].action`，但无正文检索命中时仍难以给出设备事实回答。

因此，本次不是简单扩充 JSON 数量，而是先拆开共享模板、实例、场景和运行状态，再补足一个能够演示的模拟场景。

## 3. 四类独立配置

| 配置 | 保存的内容 | 与其他配置的关系 |
| --- | --- | --- |
| 通用设备模板 | 类型、状态及测量字段、单位、支持能力、默认模拟参数、协议点位规格 | 不含场景编号、具体实例编号或必填标准条款 |
| 通用动作模板 | 动作名称、适用能力、参数类型和范围、前置条件、协议编码、预期模拟效果 | 不以场景为检索键；不要求 `source_rule_ids` 非空 |
| 设备实例 | 唯一模拟编号、显示名称和别名、设备模板引用、实际模拟地址、额定/配置参数 | 可被多个场景引用；不保存唯一所属场景 |
| 场景配置 | 设备实例引用、设备角色与关系、初始状态、模拟工况、问题示例 | 不复制设备动作定义或协议地址，不维护专属指令模板库 |

运行状态单独保存在模拟会话中。场景、设备和动作模板均是配置，不能直接成为正在变化的状态存储。

推荐新增配置目录为 `configs/device_templates.json`、`configs/action_templates.json`、`configs/device_instances.json` 和 `configs/scenario_profiles.json`。名称可由实施者按项目现有规范调整，四类职责不可合并回场景专属设备指令表。

### 3.1 点位如何复用

设备模板定义逻辑点名，例如 `position_feedback`、`trip_command`、`close_command`；通用动作引用逻辑点名。设备实例将逻辑点名映射为模拟 IEC61850 对象引用，或 Modbus 从站编号、零基地址、功能码、数据类型及倍率。

模板可以提供模拟默认值，创建实例时必须展开为可查看的实际点位。同一模拟总线内不同设备的地址冲突应在加载时检查。命令点与状态反馈点分开定义，不能把“写入了命令”直接当作“实际动作成功”。

IEC61850 保持字段级模拟，Modbus 沿用现有 PDU 编码能力；不将示例地址宣称为厂家点表或完整协议认证。

### 3.2 条款作为可选依据

标准引用保存在分析结果及可选的依据关联中，不是设备或动作模板的必填主键。已有来源关联保留其原始内容和审核状态，但不再作为独立模拟动作的必要门槛。

- 查询标准要求时，动态检索完整知识库并引用实际命中的原文，不要求固定条款 ID。
- 直接查询设备状态时，使用模拟快照即可回答位置、运行状态、测量值和告警事实。
- 判断“是否符合某标准”时，需要适用依据和可比对的数据；不足时明确给出未能确认的部分。
- 用户明确要求模拟某项动作时，按设备能力、模板和当前联锁执行模拟，不要求先检索到动作条款。
- 根据标准提出的操作建议应附实际依据；配置联锁、模拟阈值和模型解释均不能被描述为标准规定。

## 4. 首个场景：围绕两台主变的设备运维

本次覆盖主变状态查看、温升相关依据查询、冷却设备操作、开关位置与检修隔离模拟、有载调压模拟，形成可连续提问和操作的样例。以下设备及联锁均为软件测试模型，不宣称覆盖实际变电站的全部设备或操作规程。

| 通用设备类型 | 场景内实例 | 主要状态/数据 | 操作与查询能力 |
| --- | --- | --- | --- |
| 电力变压器 | 沿用现有两台主变实例 | 运行状态、冷却方式、温升、负载率、告警 | 状态、测量值和告警查询；本体不虚构启停、跳闸点位 |
| 断路器 | IEC61850、Modbus 各一台，复用现有实例 | 分合位置、测量电流、远方许可、闭锁 | 分闸、合闸及状态查询 |
| 隔离开关 | 两台，分别提供两种协议实例 | 分合位置、操作许可、关联断路器状态 | 分、合及状态查询 |
| 接地开关 | 两台，分别提供两种协议实例 | 分合位置、关联隔离和模拟带电状态 | 分、合及状态查询 |
| 冷却风机 | 两台，复用现有两种协议实例 | 运行、故障、控制模式、启停许可 | 启动、停止及状态查询 |
| 油泵 | 两台，复用现有两种协议实例 | 运行、故障、启停许可 | 启动、停止及状态查询 |
| 有载调压装置 | 两台，分别提供两种协议实例 | 当前档位、上下限、忙状态、调节许可 | 升一档、降一档、设定档位及状态查询 |

首批共 7 类、14 台场景内设备；其中 8 台复用现有主变、断路器、风机和油泵，新增隔离、接地和调压共 6 台。其余已有模拟设备及动作继续保留在通用目录中，19 台预置设备扩充为至少 25 台，不能删除未加入本场景的设备。

所有类型具有状态查询能力；测量值、告警查询按模板声明的字段提供。新设备及动作显示中文名称和可用动作，不再统一套用“模拟逆变器”等旧页面名称推断。

场景中设置 A、B 两组主变设备关系，各自引用主变、断路器、隔离、接地、风机、油泵和调压实例。编号使用现有 `SIM-` 体系，新增编号由实施者统一命名。显示别名属于实例/场景角色，不能成为后端硬编码的唯一识别方法。

## 5. 当前状态与模拟工况

每个会话从场景种子复制状态，之后独立更新。初版不需要实时后台仿真，采用明确触发的状态变化及工况切换。

提供四个初始工况：正常运行、主变温升数据偏高、冷却设备故障、停运检修。沿用现有两台主变的测量样例，其他模拟参数在配置内明确标注单位和来源为测试预设。用于标准比较的限值仍取实际适用原文；不能从工况名称倒推出标准合规结论。

切换工况或重置是明确的会话操作，不由普通知识查询触发。服务重启后会话恢复为初始种子，历史事件用于查看，不自动重放动作。

设备自身联锁来自通用模板，例如故障/忙状态/远方许可、参数上下限。涉及其他设备时，模板声明抽象依赖，场景提供设备关系；引擎据此读取关联状态，不把某个场景编号写进模板。

最小关系模拟包括：断路器分闸后相关支路电流置为模拟零值；隔离操作检查关联断路器及电流状态；接地合闸检查模拟失电和隔离条件；断路器合闸检查相关接地及闭锁状态。上述规则是明确标注的演示联锁，缺少关联设备事实时不默认为满足。风机启动仅更新风机状态，不立即伪造温度下降或标准达标。

## 6. 问答与模拟操作的流程

普通分析接口保持无状态写入。识别问题后可组合三种信息：标准原文、设备实时模拟快照、可用设备能力；并分别标明来源。

| 问题示例 | 回答及处理 |
| --- | --- |
| “变压器温升有哪些要求？” | 从新旧库检索并引用正文，不要求选择具体设备或动作 |
| “主变1现在有什么数据？” | 回答该会话的测量值和状态，不要求命中条款 |
| “主变1是否正常？” | 先说明观测状态和告警，再按能找到的适用依据做有限分析；未能确认整体健康时说明范围 |
| “风机有哪些操作？” | 从设备能力和通用动作模板列出可用操作、参数和条件 |
| “启动主变1的冷却风机” | 解析关联设备，生成模拟动作预览，展示条件、点位和预期状态变化 |
| “模拟执行这条指令”或点击“模拟下发” | 根据预览对应的服务器端命令校验并执行，返回模拟反馈和前后状态 |
| “为什么无法合闸？” | 显示具体不满足或缺失的联锁事实，相关标准只作为可用补充依据 |
| “比较主变1和主变2的状态” | 使用两份快照回答，无需唯一动作目标；写操作仍需要唯一目标 |

设备不唯一时只澄清目标，不因此清空已经可以回答的知识内容。场景外的知识问题照常查询；场景外的设备操作可以通过明确的通用实例编号进入独立模拟会话，不复制模板。

未命中标准时：设备事实及模板能力仍可直接回答；通用解释可以明确标记为解释性回答；无法确认的标准编号、限值和适用性不得编造。建议模型不可用时，保留原文和确定性设备回答。

## 7. 模拟下发与反馈

推荐新增独立模拟接口，保持原有分析和指令生成接口不自动执行：

- 创建/读取模拟会话：按场景或明确的设备实例列表创建状态副本。
- 动作预览：输入会话、唯一设备、动作和参数，后端匹配通用模板，返回命令编号、版本、点位、条件判定及预期模拟效果。
- 模拟执行：输入服务器保存的命令编号和状态版本；执行时重新读取状态、校验联锁与参数，再由内存模拟器应用动作和生成模拟反馈。
- 状态及事件查询、工况切换和重置：只作用于对应模拟会话。

前端不回传任意地址、PDU 或可执行脚本作为执行依据。协议值由后端实例映射和模板确定。重复提交同一命令返回已有结果，状态或配置版本变化时要求重新预览；失败不产生部分状态更新。多设备关系变化与目标设备状态变化作为一次会话更新处理。

模拟结果包括：成功/被阻止/失败、目标、动作、使用的模板、模拟协议字段、条件检查、执行前后状态、模拟反馈及事件编号。提供成功与反馈失败样例；失败样例不伪装成功。反馈是模拟器生成的确认信息，不是现场回执。

真实设备下发权限仍为关闭；`dispatch_allowed=false` 的原义保留。新增独立的 `simulation_execution_allowed` 和模拟执行状态，页面明确显示“模拟下发”。此规则描述本项目的模拟能力边界，不给普通问答增加额外审批步骤。

## 8. 兼容迁移及代码范围

1. 保留现有设备编号、配置参数、原有动作和来源信息，包括尚未提交的馈线断路器增补；迁移过程检查旧设备/动作没有丢失。
2. 旧配置通过适配器展开为通用模板、实例和可选的场景引用；旧 `scenario` 仅作为迁移提示，不再是通用动作匹配的必要条件。显式新配置与兼容配置重复时应报冲突，不能静默覆盖。
3. 拆分 `template_library.py` 的场景检索键、`simulation.py` 的实例/动作配置、`simulation_control.py` 的只读与可执行职责；新模拟执行器独立于协议编码器。
4. 将 `real_clause_assessment.py` 的固定变压器/条款入口改为通用设备事实查询加可选的依据分析。已有 `assessment_clause_id` 可作辅助检索线索，不能成为状态回答的门槛。
5. `grounded_advice.py` 的来源链保留“依据是什么”的说明；独立模拟指令走通用能力校验，不强迫模型每次输出动作或条款绑定。建议结果不自动触发执行。
6. 新增模拟会话/动作接口；现有 `/analyze`、`/search`、`/generate-instruction` 保持兼容且不修改状态。
7. 模板管理按设备类型、动作、协议查找共享模板，场景筛选只展示引用关系。实例页显示实际模拟编号和点位；场景页显示工况、设备及关联状态。
8. 更新与“全系统只有生成能力”直接冲突的旧断言，同时保留“分析/预览不执行、真实下发关闭”的验证。

不批量改标准库的 `rules[].action/condition/constraint`，不为配合模拟场景强造条款映射。本次不上传，不自动提交已有本地改动。

## 9. 可验收的结果

- 一个可切换工况的变电站运维场景，7 类、14 台设备，状态与实例点位可查看。
- 同一设备/动作模板被本场景和另一个测试场景引用时均可匹配，不复制指令模板；改变场景名称不改变设备动作能力。
- 新旧库知识问答、设备状态查询和多设备比较，均不以动作字段或固定来源关联为前提。
- 没有来源绑定的合法风机启停模拟能够执行；声称符合标准的回答仍需要实际来源。
- 成功的模拟下发产生可查询的前后状态和事件；不满足联锁、越界参数、缺少关系事实及模拟反馈失败时有具体原因。
- IEC61850 字段模拟和 Modbus 写值/反馈点模拟均覆盖；状态与编码的单位、倍率、布尔值/数值类型一致。
- 预览后状态变化、重复执行、不同会话引用同一实例时，分别验证重新校验、幂等和状态隔离。
- 现有 19 台设备及 47 项动作没有遗漏；新增六台设备完成相应能力，其他原有场景仍能加载。
- 普通分析、状态读取、模板测试及指令预览均不改变设备状态，真实下发持续关闭。

## 10. 本方案替用户作出的实现选择

以下为可调整的默认选择：首批 7 类/14 台、两组主变关系、四个模拟工况；写操作先预览再明确模拟执行；初版按操作推进状态，不实现连续电气/热力学仿真；会话重启恢复种子，历史事件保留用于查看。完整覆盖实际站内设备、真实规程校核和真实通信接入不属于本次设计。
