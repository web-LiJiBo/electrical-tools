# API优先问题理解 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement the approved request inline. Steps use checkbox syntax.

**Goal:** 用户自然语言先调用配置的理解模型，随后才读取设备状态、检索或预览，在线调用失败不得静默转本地操作。

**Architecture:** AnalysisPipeline统一前置一次分解，分解和意图结果传入模拟查询及条款评估，不重复分解同一请求。模拟数据仍由后端提供，模型结果不直接授权执行。

**Tech Stack:** Python/FastAPI、现有DeepSeekDecomposer、SimulationRuntime、pytest；真实DeepSeek在线回归。

**Spec:** 用户本轮“应该优先调用api”，承接此前“先统一理解意图与约束，再分流；最终后端校验”的说明。

## Global Constraints

- 只改本地，不推送、不提交；保留既有未上传审阅文档。
- 在当前已约定的本地演示目录实施，避免另建工作副本导致用户运行旧代码。
- 所有自然语言/analyze及复用它的生成入口先分解；结构化状态/执行接口无需调用模型。
- DeepSeek在线理解失败显式返回模型未完成，不生成候选。显式离线配置保留兼容，不作为本次有效性验收依据。
- 相同请求的分解在状态及条款分支复用；不以关键词分流省略模型调用。
- 模型分解不是设备事实、协议载荷或执行授权。场景独立身份、自动汇总共享状态不变。
- 不扩展本轮为检索性能优化或全部历史问题修复。

## Review Focus

- 状态/能力/直接操作都在读取快照前完成模型理解。
- 否定、疑问、条件和多动作不得因提到启动而产生无条件预览。
- 对设备实体的并列和所属关系保持区别；未知数字名称不泛化为同类型全部设备。
- 在线认证/超时/格式失败不得由本地分支悄悄成功；错误不暴露凭据。
- 主变评估不为同一请求再次调用分解；保留独立建议调用。

## Decisions

- 直接在用户约定本地目录修改，保留原HEAD作为差异基准；不用自动commit和worktree流程替代当前本地预览。
- 仅明确设置llm_decomposition.allow_offline_fallback=true的离线配置保留兼容；关闭建议模型不代表允许理解降级。
- 单动作入口暂不编译用户条件式动作；理解后的约束显式保留并提示，避免转换成无条件动作。
- API通过scenario.query_kind输出明确问题类型，缺失或无效则在线请求显式失败；已知同义intent字段规范化，不补造业务内容。
- 共享生成限制覆盖直接模拟和模型建议转换；模型已识别的自然语言条件不能被search意图绕过。
- 最终完整套件478通过、15跳过；新增39个回归。23个用户问题、3个分解对照加6个复测共46次真实调用，资料保留初验问题和修复后结果，不将接口成功等同于答案正确。
