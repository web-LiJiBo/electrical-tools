# 主变与附属设备比较遗漏修正

本次随其他审查问题修正发布到更新分支 `feature/multi-device-actions-20261109`，未合并到远端 `main`。

## 问题与原因

实际调用在线 `/analyze` 复现两种情况：

- “比较主变1和主变1的冷却风机的当前状态”仅返回风机。共享属主展开将同一主变的两次提及合并成风机目标，后续关联解析也会整体移除主变。
- “比较主变1及其冷却风机的当前状态”仅返回主变。后端未处理相邻“及其”所属关系，虽然模型识别到主变和风机，最终目录目标仍少了一台。

## 修正行为

按每次设备名称出现的位置区分独立目标和所属关系，独立提及的主变保留；主变后紧邻“及其”“与其”“和它的”等短语时，使用当前场景目录的对应设备关系补充附属设备，不跨主变或场景猜测。

可直接输入：

> 比较主变1及其冷却风机的当前状态

返回主变1及其冷却风机两台设备的当前模拟状态。“启动主变1的冷却风机”仍仅生成风机预览。“主变1和主变2的冷却风机”沿用两个不同属主的风机展开行为。未知编号继续提示未登记。

## 验证

- 新增32项回归用例，覆盖正反提及顺序、代词、风机/油泵、共享属主、设备编号、未知编号和两个场景入口。
- 全量测试：570项通过，15项因历史本地来源/人工标注资料缺失跳过；1项已有依赖弃用提示。
- 真实 DeepSeek API：两个入口共12次在线分析通过，确认比较结果包含正确设备及快照状态；单独风机启动仍只生成风机预览，查询及预览前后会话状态一致。
- 原始响应与测试日志位于本地 `.tmp/owner_accessory_20261109/`，不纳入发布文件。

本地服务已重启至修正后的代码，刷新页面后可体验；代码修正在 `application/simulation_query.py`，未修改设备身份、模板或场景状态存储。
