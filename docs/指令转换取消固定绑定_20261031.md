# 指令转换取消固定条款绑定：实现与维护说明

功能日期：**2026-10-31**；文档修订：**2026-11-01**。保留原文件名以兼容已有链接。本说明随本次功能与文档一起发布，发布范围和发布前结果见[本次更新说明](本次更新说明_20261101.md)。操作方法及工况配置见[变电站模拟工作台](变电站模拟工作台.md)，本文重点解释机制、接口和维护位置。

## 1. 取消什么，保留什么

原“条款分析 → 动作建议 → 指令转换”依赖条款与设备动作模板的固定关联。新链路由模型引用本次检索原文，再用通用设备模板生成模拟预览。

| 项目 | 原方式 | 当前方式 |
| --- | --- | --- |
| 来源关联 | 提前配置 `source_rule_ids/source_bindings` | 模型从本次提供的来源中返回 `rule_ids` |
| 字段匹配 | 条款动作、条件、原文与绑定记录匹配 | 不要求条款与模板逐字段相等，也不要求唯一依据 |
| 转换条件 | 依赖来源绑定和条款可执行条件 | 设备支持的动作、可信模板、当前事实、关联联锁和版本 |
| 转换入口 | 旧来源绑定生成路径 | 明确动作与模型建议共用 `SimulationRuntime.preview` |

旧 `generate_grounded` 已移除。`rules.action`、`rules.condition`、`rules.constraints` 不再是**动态建议转换**的硬门槛，可保留空值或原有自然语言；仍可参与其他检索、解释和旧有分析，不是删除整个系统的语义验证。原文条件不会直接编译成设备执行条件。

没有批量删除或修改标准 JSON，不为通过转换补造标准动作、条件或约束。模板历史 `source_rule_ids/source_bindings/source_scope` 继续保留/读取，载荷里的 `source_rule_ids` 也可能显示模板旧值；**本次引用应读取 `candidate.evidence/analysis_evidence`**，不能把历史字段当成本次模型依据。

仍须校验引用来自本次输入、正文存在、目标设备有效，以及明确的来源场景冲突。引用存在与模拟转换通过均不等于来源语义、专业审查或适用性已确认。

## 2. 三条处理路径

入口为 `AnalysisPipeline.analyze`，先尝试 `answer_simulation_query`，响应由 `_respond` 汇总状态。

1. **普通问答/设备事实。** 普通标准问题保留完整库检索。模拟状态、数据、比较及可用动作可直接读取当前快照，标记 `simulation_factual=true`，不要求动作条款或模型指令。含“标准、条款、依据、要求、限值”等词的问题不被通用事实分支吞掉；专门温升评估仍可结合来源。状态回答不自动代表整体健康或合规。
2. **明确模拟动作。** 如“启动主变1的冷却风机”，在模拟模式、唯一目标及动作支持等条件满足时直接调用 `runtime.preview`，无需条款依据。命中当前否定、疑问、取消词组检查的表述不进入直接动作分支，例如“不要启动”“是否启动”“如何启动”；这是有限词组规则，不能保证识别所有问句，“启动主变1的冷却风机吗？”仍可能生成预览，但不会执行。多目标只返回说明。`set_tap` 可从文本提取档位，其他参数取 `parameters.action_parameters`。含标准依据的动作问题继续来源链路。
3. **条款后的模型建议。** `GroundedAdviceService.enrich` 组织检索正文、审查标记、当前设备快照和允许动作。模型输出一条草案或 `null`；经结构、引用、目标及动作文本校验，`convert_advice` 生成动态证据，再调用同一个预览入口。`instruction=null` 时 `conversion.status=not_proposed`，保留文字建议，不解释为设备一定正常。

三条路径均不调用 `execute`。原首页输入框、业务场景、参数及五个结果页签保持不变；模板管理页仅调整必须绑定相关提示，布局、样式、控件和筛选保持原样。只有在原“操作建议”核对后**明确点击“模拟下发”**才尝试改变模拟状态。

## 3. 模型与来源契约

### 输入

`grounded_advice.py` 的 `PROMPT` 将问题和原文视为数据，要求不生成地址、载荷、代码或阈值表达式。输入包为：

- `query`、已有 `assessment`；`device` 含 `device_id/display_name/protocol/device_type/state/runtime_facts`，没有唯一目标则为空。
- `allowed_actions`；按动作码组织的 `action_templates`，每项含 `parameter/unit/minimum/maximum/source_scope/expected_feedback/configured_parameter_fact/scope/display_name`，其中 `scope=simulation_only`。
- `clauses`：先选中来源、再匹配来源，去重后最多5项；空正文、仅标题、清单缺失及保留原始类记录不进入建议来源集合。

每项 `clauses` 含9个来源字段：`rule_id`、`standard_id`、`version`、`chapter_path`、`quote`、`source_text`、`action`、`condition`、`manual_review_required`。`quote=Rule.content`，`source_text` 优先取 `metadata.source.source_text`，缺失回退正文。动作/条件是来源说明，不作为模型可改写的执行条件。

### 严格输出

顶层恰为 `summary/rule_ids/suggestions/instruction`，不接受额外键。文本字段均须非空且不超过3000字符；引用数组非空，且每个ID必须属于本次提供的来源。`suggestions` 可为空，最多5项，每项恰含 `text/rule_ids`。`instruction` 为 `null` 或恰含 `text/device_id/action/parameters/rule_ids`；`parameters` 必须是对象，动作须为目标设备允许动作，参数细则交给模板校验。顶层、建议及指令各自引用有效即可，不要求三者数组完全相同。

以下是**模型输出结构示例，不是真实条款或在线模型实测回答**。占位ID必须替换为本次 `clauses` 中实际检索ID，分析及建议也须按真实原文重写；未替换会被拒绝。该示例本身不证明风机应当启动。

```json
{
  "summary":"依据实际原文和快照说明分析结论、适用性与待复核事项。",
  "rule_ids":["<需替换为本次检索实际rule_id>"],
  "suggestions":[{"text":"按实际原文说明建议理由。","rule_ids":["<需替换为本次检索实际rule_id>"]}],
  "instruction":{
    "text":"启动冷却风机",
    "device_id":"SIM-IEC-FAN-01",
    "action":"start",
    "parameters":{},
    "rule_ids":["<需替换为本次检索实际rule_id>"]
  }
}
```

仅支持人工核查或缺动作依据时应返回 `instruction:null`，不能用空引用凑出指令。

### 响应来源与动态证据

`data.advice.sources` 是上述输入 `clauses` 的被引用子集，汇总顶层、建议和指令引用，**不含 `support_status`**。`data.advice.evidence` 仅按 `instruction.rule_ids` 去重生成，每项实际含11个键：

| 字段 | 来源/含义 |
| --- | --- |
| `rule_id` | 来源规则ID |
| `standard_id/version` | 知识单元的标准标识及版本 |
| `clause_id/chapter_path` | 条款标识及章节 |
| `quote/source_uri` | 规则正文及知识单元来源位置；空来源位置不补造 |
| `manual_review_required` | `metadata.audit.manual_review_required is True` |
| `support_status` | 待复核为 `pending_review`，其余为 `analysis_reference`；均不是已确认支持 |
| `applicability_status` | 适用性校验结果；明确场景冲突强制为 `fail` |
| `applicability_notes` | 校验器说明，包括实体匹配无法确认等 |

`analysis_notes` 汇总去重的适用性说明及待复核提醒；待复核提醒不一定同时位于每项 `applicability_notes`。场景取快照 `scenario_id`，再回退设备 `scenario`，最后 `general`。来源明确指定其他场景时阻断；空场景或 `general` 不按此阻断。实体不确定和待复核保留标记，不冒称已经专业审定。

## 4. 目标、事实与模板检查

`advice_context` 优先使用 `parameters.simulation_session_id`，未传时复用默认模拟会话；显式会话不存在会保留来源分析并阻止转换，不静默替换会话。`_targets` 优先合并文本 `SIM-...` 与 `parameters.device_id/device_ids`，统一大写去重；没有显式编号时匹配显示名/别名，再按设备种类查找。

“主变1的冷却风机”通过场景 `groups` 的 `cooling_fan` 角色解析为风机，而非主变本体。建议路径还兼容“模拟变压器1”“模拟断路器1/2”“模拟逆变器1/2”“模拟换流阀1”等历史名称，避免基础设备名误匹配馈线设备。最终目标须唯一、登记在目录中、属于当前会话，并与模型目标完全一致；涉及真实/实际设备的建议转换被阻止。

无会话编号时，**建议路径**可为已登记但不在默认场景的唯一目标创建单设备会话，成功预览返回新 `simulation_session_id` 供后续复用；**直接事实/动作路径**不进行这种补建。显式会话不得借兼容规则跨会话操作。

事实来自服务器快照 `state/runtime_facts`，不采用用户同名测量值；回归中用户填 `current=999`，模型实际看到设备快照 `current=120`。参数名、范围、条件、效果来自可信动作模板；IEC对象、Modbus地址、功能码、倍率来自设备/实例及动作映射，模型不能提供协议点位或可执行表达式。

`SimulationInstructionService.generate` 与运行时 `_prepare` 检查：

- 设备支持动作；参数字段必须与模板严格一致，无参数动作为 `{}`。数值须有限且在范围内，整数不接受布尔或小数。
- 模板 `condition/constraints` 使用快照事实计算，缺失或不满足时阻断。`configured_parameter_fact` 要求参数等于配置事实，`decrease_only` 要求小于当前状态。
- IEC必需对象字段、Modbus FC05/06类型/地址/倍率及无损编码有效，不能用截断凑编码。
- 场景组唯一定位关联角色，按 `relation_requirements` 复核联锁；缺关联、缺事实、类型无效或不满足均阻断。
- 在副本验证 `simulation_effects` 和独立 `feedback_mapping`，命令点与反馈点分离。

`runback_power` 不能由温度阈值推导目标功率。提示要求缺设备回降配置时不给动作；后端还要求文本MW数值等于 `target_power_mw`、不得混入“闭锁”，并符合配置事实、回降及模板检查。

模型 `text` 须匹配动作；未知词表动作可按模板 `display_name` 匹配。“不要启动”“是否启动”“启动吗？”“启动与否待确认”等否定/未决表达报 `invalid_model_output`；“启动风机并停止油泵”“启动风机并合闸”等多操作组同样拒绝，同组同义词只计一次。用户“不要生成建议”“取消指令”等另在转换前阻止。这是当前正则/词组检查，不是完整语言证明，扩展动作需同步维护回归。

每次 `enrich` 先删旧 `simulation_preview/instruction_generation`，清空旧候选载荷。模型禁用/失败、输出错误、无正文、无动作、取消等均不能保留旧可执行预览。错误使用固定错误码，不回显供应商异常正文；`_respond` 消除无载荷的旧 `generated` 假象，模型错误可使响应为 `partial`。前端在问题、参数、场景、模拟勾选改变时使预览失效，请求中修改输入也不能执行旧结果。

## 5. 版本、状态提交及证据传递

模型调用前保存快照，转换通过以下服务器调用核对同一版本：

```python
runtime.preview(session_id, device_id, action, parameters,
                evidence=evidence, expected_version=snapshot["version"])
```

这两个仅关键字参数兼容旧位置调用。锁内要求分析版本为非负整数且等于当前版本，模型等待期间状态变化会返回 `blocked`、空载荷、无命令，须重新分析。直接动作/HTTP预览未传分析版本，仍保存预览时版本并在执行复核。

成功预览只保存服务器 `command_id`、参数、证据及目录指纹，不改变状态。执行提交命令编号和预览返回的版本，再检查当前版本、目录指纹、事实与联锁。成功执行、切换工况、重置都会提升版本；配置变化要求重建会话和预览。效果先写副本，反馈成功且事件写入后才提交状态；反馈失败或事件存储失败不提交。有效命令的结果含失败均会保存，重复执行返回原结果；跨会话命令不能使用。

证据沿 `advice.evidence → preview.candidate.evidence/analysis_evidence → 服务端command.evidence → 执行重建候选 → result/events` 传递。输入、内部保存、返回及历史读取均深拷贝，修改嵌套返回对象不能污染服务端证据。阻断预览保留证据但清空载荷；执行不接收客户端替换的地址、参数或证据。

状态在内存，事件可写 `data/simulation/events.jsonl`；重启可按旧会话编号只读查询历史，不恢复状态，不自动重放动作。历史引用记录当时分析，不代表知识库更新后的重新认证。

## 6. 实际接口与判读

创建会话：`POST /simulation/sessions`，请求 `{"scenario_id":"substation_maintenance","condition":"normal"}`。保留返回 `session_id`，再请求 `POST /analyze`：

```json
{
  "query":"启动主变1的冷却风机",
  "parameters":{"simulation_mode":true,"simulation_session_id":"<返回的session_id>"}
}
```

若需来源建议，将问题改为“依据本次检索条款，主变1的冷却风机应如何处理？”。能否给指令取决于实际原文、模型及校验，不保证该问题一定生成动作。

也可直接 `POST /simulation/sessions/{session_id}/preview`：

```json
{"device_id":"SIM-IEC-FAN-01","action":"start","parameters":{}}
```

该HTTP接口只接受 `device_id/action/parameters`，**不接受客户端 `evidence/expected_version`**；两者用于上节服务器Python调用。直接预览证据默认为空，不伪造来源。

分析预览位于 `data.simulation_preview`，会话在 `data.simulation_session_id`；直接预览接口直接返回预览对象。核对 `status=generated`、`simulation_execution_allowed=true`、`command_id` 和整数 `expected_version`。真实设备下发始终为 `dispatch_allowed=false`。

明确点击“模拟下发”后调用 `POST /simulation/sessions/{session_id}/execute`：

```json
{"command_id":"<本次返回的command_id>","expected_version":0}
```

`0` 仅在预览返回0时适用，必须使用实际返回版本。响应检查 `status/before/after/feedback/relation_checks/analysis_evidence`，事件通过 `GET /simulation/sessions/{session_id}/events` 查看。接口拒绝附加地址、载荷、状态；未知会话等返回404，字段/类型错误返回422，业务阻断通常为响应 `status=blocked`。

建议转换另看 `data.advice.conversion` 的 `status/reason`，成功还含 `rule_ids/template_id/source_binding_required=false`；生成记录的 `basis=dynamic_citations_template_preview`、`generation_only=true`。`validation` 通过范围仅为模拟模板、参数、联锁、版本；`processing` 分别呈现来源、建议和指令状态，不能仅凭顶层成功推断已执行。

## 7. 代码定位与维护

运行时实际文件名为 `simulation_runtime.py`，不是 `runtime.py`。

| 位置 | 职责 |
| --- | --- |
| [analysis_pipeline.py](../src/standard_knowledge_service_v2/application/analysis_pipeline.py) | `analyze`分流、`_respond`汇总及报告/审计 |
| [grounded_advice.py](../src/standard_knowledge_service_v2/application/grounded_advice.py) | 提示、来源包、建议生命周期、严格结构/动作文本验证 |
| [advice_conversion.py](../src/standard_knowledge_service_v2/application/advice_conversion.py) | `advice_context`目标；`dynamic_evidence`证据；`convert_advice`版本预览 |
| [simulation_query.py](../src/standard_knowledge_service_v2/application/simulation_query.py) | `_targets`名称/关联角色、`_action`、事实与直接动作 |
| [simulation_access.py](../src/standard_knowledge_service_v2/application/simulation_access.py) | 应用运行时、默认会话、事件位置 |
| [simulation_runtime.py](../src/standard_knowledge_service_v2/instruction_engine/simulation_runtime.py) | 预览、执行、关系联锁、版本、深拷贝、回滚、事件和幂等 |
| [simulation.py](../src/standard_knowledge_service_v2/instruction_engine/simulation.py) / [simulation_catalog.py](../src/standard_knowledge_service_v2/instruction_engine/simulation_catalog.py) | 确定性模板/编码；设备模板、实例、场景及旧配置组合 |
| [simulation_routes.py](../src/standard_knowledge_service_v2/api/simulation_routes.py) / [original-simulation.js](../frontend/original-simulation.js) | HTTP白名单；原界面会话、预览失效与明确执行 |

维护步骤：

1. 新来源通过正常知识库流程入库，保持正文、ID、版本、来源、场景及审核元数据可追溯；检查实际检索集合，不给设备补固定绑定，不将测试合成文本纳入真实标准库。
2. 新设备/动作在 `configs/device_templates.json`、`action_templates.json`、`device_instances.json` 维护能力、参数、条件、效果与点位，在 `scenario_profiles.json` 维护关联角色和工况；先验证模板、反馈及联锁，再验自然语言入口。
3. 扩展措辞时同步核对允许动作、模型动作词/多动作分组、`simulation_query._action`及显示名，覆盖正确、否定、疑问、混合与不支持动作。
4. 修改字段时分别核对输入来源、响应来源、动态证据结构；验证嵌套深拷贝、执行重建、重复执行及重启历史。不要将参数/协议真值移入提示词或允许HTTP执行接收载荷。
5. 发布前跑集中与完整回归，并验证原界面两步操作；记录实际日期和结果到[更新说明](本次更新说明_20261101.md)，不要将历史结果写成本次新跑结果。
