## 补充规则及证据

1. 通过历史导入记录重建发布索引，核对原Excel文件的SHA256，再按原索引行关联条款；历史首批100条缺少索引行号时，采用编号和完整原文精确匹配，保留重复来源。
2. 从具体来源文件名识别标准系列、分部分编号和年代号。分类号、备案号、标准类别文字均不作为正式编号。没有正式编号的内部制度保留名称和独立文档标识，不编造标准号。
3. 名称结合原文件、表头及本地既有整理目录补齐；名称来源及是否经过官方核对的历史状态保留在来源目录中，未将本地目录视为新的官方认证。
4. 适用范围来自该份原文的“范围”“适用范围”“总则”等段落，保留原文措辞和行号，不从标准编号或标题推测设备条件。跨行、合并单元格及OCR误识别仍需结合原件复核。
5. PDF页码仅由完整原文在去空白和Unicode规范化后的文本中精确匹配得到，采用从1开始的物理PDF页码。短文本、扫描件及无法匹配的文字不填猜测页码，Excel原文坐标仍保留。
6. 年份表示标准年代号或内部文号年份，不表示实施日期，也不代表该版本当前仍有效。本次未进行全库现行性核查。

三份来源文件名使用了调整后的标准代号，而正文仍用旧代号，已核对官方公告并保留旧编号：

- `XF/T 970-2011`与`GA/T 970-2011`的关系依据[应急管理部消防救援领域标准重新编号公告](https://www.mem.gov.cn/gk/zfxxgkpt/fdzdgknr/202012/t20201207_374310.shtml)。
- `YJ/T 3052-2015`与`AQ/T 3052-2015`、`YJ/T 9011-2019`与`AQ/T 9011-2019`的关系依据[应急管理部2025年第1号公告](https://www.mem.gov.cn/gk/zfxxgkpt/fdzdgknr/202501/t20250126_513844.shtml)。

## 剩余缺项

- 11份内部制度、1,291条记录的来源文件名未带正式编号，也没有可确认的文号或版本，编号和版本留空。
- 6,098条记录未在现有来源中找到完整的适用范围段落，明确标记`scope_not_located`。其中早期来源多为从第3或第4章开始的条款摘录；不能将正文中的零散设备要求当成整份标准的范围。
- 许多PDF是扫描件或本地未保留；没有唯一PDF匹配页码的记录，仍需通过原Excel坐标查阅摘录，或补充原版文件/OCR后核对PDF页码。
- 范围段落不等于全部业务适用条件，原有自然语言条件未被自动编译成可执行规则，专家复核及候选指令生成门禁保持原状态。

具体文档及涉及条款数量见`datasets/supplemental/标准元数据待核验清单.json`。

## 文件和验证

`metadata.original_standard_id`保存原编号，以保持条款、实体和规则的内部标识稳定。JSON文件名保留历史名称，当前编号以正文的`standard_id`为准。原子条款索引保留导入时的内容及哈希，不覆盖历史证据。

完整修改前备份位于`artifacts/metadata_enrichment_20261026/applied/original_records.zip`；同目录的`record_changes.jsonl`保存逐条映射，`verification.json`保存逐条校验结果。备份和中间记录已排除出Git版本管理。

相关验证为16项通过、1项跳过。额外运行建议生成测试时，有2项既有失败；在进程内换回修改前HEAD的标识函数后，两项仍以相同原因失败。该既有问题未在本次元数据任务中修改，不能据此宣称全部功能测试通过。

补充脚本为`scripts/enrich_supplement_metadata.py`，默认只生成预览，显式传入`--apply`才会在完整备份后写入。需要历史原Excel、读取结果、导入记录、原始索引及本地名称目录；读取PDF需要PyMuPDF。本次使用应用提供的PDF运行环境处理，没有安装新依赖。
