# 多设备、多动作指令预览与逐条模拟下发

更新日期：2026-11-09。上一发布基准：`93f368a94216443e72edf4a79734a39252b2e97f`。

本次将首页原有单设备指令预览扩展为多条指令列表。一次问题可以指定多台设备执行相同或不同动作，也可以为同一台设备的不同参数分别设定目标。系统逐条显示目标、动作、参数、校验结果和模拟下发按钮。

## 用户能看到的变化

| 输入问题 | 当前行为 |
| --- | --- |
| 启动主变1和主变2的冷却风机 | 两台风机各生成一条启动预览 |
| 启动主变1的冷却风机，同时停止主变2的油泵 | 风机启动、油泵停止分别绑定，不向每台设备套用所有动作 |
| 将新能源逆变器（IEC61850）的有功功率设为120kW，同时将其无功功率设为30kvar | 同一设备生成两条独立指令，目标值分别为120kW和30kvar |
| 将新能源逆变器（IEC61850）的有功功率设为120kW，同时将新能源逆变器（Modbus）的有功功率设为80kW | 两个目标值分别属于对应设备，不互相冲突或串台 |
| 有功目标越界、无功目标合法 | 越界条目显示阻断原因及输入值，合法条目保留预览；页面显示部分指令可用 |

场景选择“变电站设备运维”或“新能源并网”，勾选模拟模式，业务参数保持`{}`。点击“分析问题”后，在“操作建议”查看每条指令。协议载荷和联锁轨迹默认折叠，可按需展开。

页面分别统计设备数和指令数，例如“1台设备、2条指令”。每次点击“模拟下发本条”只执行对应指令；执行后，其余未执行的可用条目按最新状态重新预览，仍需再次核对并点击。已处理条目保留独立反馈，输入变化会禁用旧按钮。

## 本次处理规则

- 修正编号与中文名称混用时漏选目标的问题，补齐“主变1和主变2的冷却风机”等并列所属关系解析。
- 对明确分隔的操作分别调用模型理解和既有单动作管线；目标、动作、数值及单位按各条原文核对，不把全局动作或参数广播到所有设备。
- 后续省略设备时，仅允许继承上一条唯一设备的明确参数赋值；目标不唯一或未知时不猜测。
- 设备名出现在等值赋值的条件字段时，只接受原文和目录可精确对应的目标标注；真实的执行前提、运行条件和非目标状态约束仍被阻止。
- 每条继续使用现有参数范围、联锁、版本和反馈检查；执行结果未知时禁用后续下发，要求查询状态后重新分析。
- 对未知显式动作增加检查，避免直接索引设备动作时产生未处理异常。

## 边界与兼容性

当前功能用于模拟设备直接操作入口，采用逐条确认，不提供整组自动执行或事务回滚。先后依赖、同设备启停冲突、重复或覆盖同一状态的操作，需要明确意图并拆分处理。一次最多解析8个明确子请求；模型理解不完整时不返回缺项指令列表。

多动作问题先理解整句，再分别理解子请求，因此会增加模型调用次数和等待时间。不要用同一份action/action_parameters覆盖多个不同操作，各条目标值应写在对应正文中。

各业务场景保持独立设备身份，自动汇总继续与所属场景共享同一设备状态。本次没有新增设备、修改标准库或引入运行依赖。

## 接口变化

`/analyze`的data增加`simulation_batch`，包含items、generated_count、blocked_count和状态。每项保留独立preview、command_id、目标、动作、参数和单位；不同动作条目另外提供原文子请求及逐条理解结果。

`/generate-instruction`同时返回`simulation_batch`和`simulation_session_id`。批次的单条candidate_instruction为空，防止旧客户端仅执行第一条；批量调用方应显式处理items。单设备预览响应和会话preview/execute接口继续兼容。

## 代码与验证

主要变更位于application/multi_device_preview.py、mixed_operation_preview.py、simulation_query.py、analysis_pipeline.py、api/routes.py及frontend/original-simulation.js。测试覆盖目标完整性、动作与参数归属、独立联锁、版本失效、冲突及失败保护，并增加相应前端用例。

实现阶段相关Python回归179项通过，前端Node测试11项通过。最终真实Chromium验收8个根问题，理解来自实际DeepSeek接口；四条页面模拟指令执行成功，页面错误为0。测试另外准备了运行中的油泵，用来核实停止动作确实改变状态，未将准备步骤计入四条页面执行。

发布前重新运行完整本地套件：538项通过、15项跳过、0失败；跳过项主要因历史来源/人工标注资料未安装，未计为通过。测试进程移除了生产密钥并阻断外部连接，未发生真实外连尝试。上述完整套件与前面的真实API浏览器验收分开记录，不能以离线回归替代在线验证。

原始响应、调试记录、运行日志和截图留在本地，不作为发布文件上传；密钥由使用者自行配置。

## 升级后使用

更新代码后重启后台，再刷新首页。只刷新页面不能让已运行的后台加载新功能。本次无需安装新增依赖。可按上述示例查看两条指令并逐条模拟下发。
