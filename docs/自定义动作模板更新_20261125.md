# 自定义动作模板更新

日期：2026-11-25。已随2026-11-25统一更新发布；以下为本地验证记录。

## 新增指令模板

在“自定义配置 → 指令 → 新增指令”中，可选择新增自定义动作，填写独立的动作编号、中文名称、参数、前置条件、结果字段和设备报文配置。原有预设动作继续兼容。

- 固定值动作：写入布尔值或数值，例如清除告警时写入 false；状态变化由所填结果字段和目标值确定。
- 参数动作：定义数值或整数参数编号、范围和结果字段，例如参数 target_ratio 写入 duty 字段。参数编号不必与结果字段相同。
- 前置条件：可填写最多10项字段条件；明确不填时表示该模板没有前置条件，其他范围、类型及报文校验仍然执行。
- 报文映射：为关联设备配置 Modbus TCP 或 IEC61850 的控制点、反馈点及编码等完整信息，与指令一起校验、保存。

模型从当前设备能力目录读取动作名称、参数、范围、条件和状态效果，不再要求新增动作编号属于原有枚举。执行含义由模板明确配置，不从编号文字推测。

本次支持一个动作控制一个值、改变一个结果字段；未加入多参数工作流、循环、延时或任意脚本。设备类型仍使用现有自定义模块支持的类型。配置保存在本地，保存后按提示手动刷新再问答。

## 2026-11-26本地修正与限制评估（本轮统一发布）

### 已修正

- 通信变更按整台设备比较：预览显示新旧通信配置与所有受影响动作，用户勾选后才能保存，后端也要求确认。新增设备或通信未变化时不增加确认步骤。解除最后一个覆盖关联、恢复原通信配置时同样核对影响，不会静默改变其他动作的地址。
- 同一设备的跨动作点位按读写用途、结果字段、编码和完整寄存器范围检查。写入与其他动作反馈重叠、不同字段或不同编码共用点位会阻止保存；同一状态、同一编码的启停共用命令点和反馈点继续允许。
- Modbus区分线圈、离散输入、保持寄存器和输入寄存器，输入与保持寄存器可以使用相同数字地址，不误判成同一点位。依据：[Modbus官方协议说明](https://www.modbus.org/introduction-to-modbus)。

### 哪些限制适合放开

|建议|内容|应保留的约束|
|---|---|---|
|优先开放|用户定义设备类型、中文名称和别名|类型只是业务分类；动作仍须有字段与协议映射。同一适用范围内的别名不能造成多个设备身份混淆。|
|优先开放|扩展常用单位或登记新单位|原单位可以保留；自动换算必须有明确量纲和换算关系，不能让模型猜倍率。|
|优先开放|本地条款编辑、删除、单独导出|保留原文来源和版本，编辑后更新索引，不能把用户改写冒充标准原文。|
|有条件开放|删除已发布自定义设备；修改已有字段|删除前展示关联影响并处理引用；字段改名、类型或单位变化须迁移映射。设备编号、场景归属仍保持稳定，不直接把实例换成另一场景身份。|
|分阶段开放|一个控制值带多项明确状态变化、枚举值到协议数值的映射|主控制值、反馈字段和每项效果明确；不凭动作名称推测。|
|分阶段开放|或条件、跨设备条件、多参数/多报文动作|先建立明确条件结构、有效设备引用、执行顺序及失败策略，再开放界面。不能仅增加自由文本框。|
|暂时保留|500条数量、30字段、1MB配置等容量限制|先做大配置加载与保存性能验证，再按实际需要调整；不直接取消上限。|
|继续保留|类型、范围、协议编码、点位冲突、身份和来源证据校验；生成与执行分离|不增加任意脚本或eval，不自动下发，不在设备歧义时替用户选择，也不允许模型绕过校验。|

以上是后续功能建议，本轮没有直接扩大设备类型、单位或动作表达范围。本地保存仍为默认，不新增跨电脑同步需求。

## 2026-11-26：开放设备类型、别名与单位登记（本轮统一发布）

上一节“优先开放”的设备类型、别名与单位登记现已落实，条款编辑删除仍为后续建议。

- 新增“类型与单位”工作区：登记类型编号及名称；类型只是业务分类，新增类型须自行配置明确动作、字段和报文，不自动继承其他类型的操作。
- 自定义设备表单增加别名，每台最多20个、每项2—40字符。别名不能冒用已有设备编号、名称或别名，登记后进入当前目录，参与模型理解及程序身份核验。
- 单位可选择“不自动换算”，仅接受相同单位；也可指定已有基准单位、倍率和偏移。规则为“基准值=新单位数值×倍率+偏移”，支持明确的多级换算；循环、未知基准、非正或非有限倍率均拒绝。常用A、kA、Ω、kΩ、MΩ、mW和档位单位可直接选择，大小写保留。
- 同一套换算用于目标值规范化、动作参数和用户补充当前值；报文仍写入模板字段的单位，不让模型自行猜测倍率。已经使用的单位及其依赖基准不能直接改变含义。
- 设备类型、单位登记通过可选definitions随统一配置保存；旧版三数组格式继续兼容。批量合并逐项预览登记冲突；选择导出设备/指令时带上必要类型、单位及其换算依赖，别名随设备一起导出。也可在登记区单独导出全部登记内容。
- 登记内容与设备、指令、报文一并校验保存，未保存修改仍属于当前窗口草稿；每类登记最多100项，仍仅保存在本地。

实际页面完成登记、嵌套创建设备、别名输入、动作和完整报文配置，以及统一保存。真实DeepSeek用一道新问题同时验证新类型、两个别名和单位换算：0.002GΩ规范为2MΩ，生成1条候选、返回1项当前值查询，并生成完整Modbus请求包，共2次模型调用，未执行，设备状态不变。通过问题已纳入正常问题清单；原始记录在本地`06-工具/审阅记录/20261126_开放类型别名单位/`。

## 2026-11-26：类型与单位合并进填写流程（本轮统一发布）

取消独立的“类型与单位”导航页。新增/编辑设备或指令时，在类型选择旁直接新增类型；在数值字段的单位选择旁直接登记单位及换算关系，确认后立即回选，保留原表单输入。类型、单位仍统一存储和跨设备复用，已有配置文件及导入导出格式不变。

新增类型、单位属于当前表单的嵌套草稿。取消外层设备或指令窗口时一并撤销，不留下孤立登记，也不会提前写入本地文件；确认外层表单后再统一校验保存。设备列表下可查看已登记的类型与单位，批量区保留单独导出登记内容的按钮。旧`tab=definitions`地址转到设备页。
